## 1. 待办清单（按优先级）

### P0 · 预扣估算修正（1 小时，先做）

- 事实：`token_estimate_default=2000`，真跑一次热力图任务实际 12,937（偏低 **6.5 倍**）。
  预扣不足 → 钱包被"事后补扣"，用户看到余额跳变；预算门（`balance < estimate` 短路）形同虚设。
- 方案：按会话历史长度动态估——`estimate = 2000 + 近期对话 token 数 × 1.2 + 任务文本长度`；
  或直接把默认值提到 10000 并在管理端可调。
- 验收：单轮任务 reserve ≥ settle（偏差 < 20%）。

### P1 · 账本对账视图（半天，数据已有）

- `token_ledger` 三列已在 2.4.2 写入，**只缺界面**：管理端加"任务对账"页，
  每行 `reserve / actual(=input+output) / billed(=settle) / 差额`，差额按缓存折扣自动解释。
- 支持按用户/日期筛选，异常行（settle 与公式不符）标红。

### P2 · LLM 调用级可观测（1 天，从 2.4.2 P3 顺延）

- 新表 `llm_call(run_id, step, agent, model, messages_json, response_text, prompt_tokens, completion_tokens, ms)`。
- `/api/v1/runs/{id}/context`：返回每次调用模型实际收到的 messages（手机号脱敏）。
- 管理端任务详情**时间轴最小版**：步骤列表（序号/Agent/工具/耗时/成败），点开看"收到什么、返回什么"。
- 为什么现在做：2.4.2 的「需要」事故靠日志才定位；这张表能让同类问题 5 分钟定位。
