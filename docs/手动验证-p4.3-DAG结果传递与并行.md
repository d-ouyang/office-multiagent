## 2. 核心正例：三段链（清洗 → 按城市分析 → 生成报表）

**目的**：验证「有依赖的子任务接上一步的结果」。用可手算的数字当标尺。

**准备**：上传一份 6 行的表格（数字必须能手算）：

```bash
cat > /tmp/sales_oct.csv <<'CSV'
日期,城市,门店,销售额
2026-09-01,上海,徐汇店,1280.50
2026-09-01,安庆,迎江店,860.00
2026-09-02,上海,徐汇店,1420.00
2026-09-02,安庆,迎江店,940.00
2026-09-03,上海,浦东店,1650.00
2026-09-03,安庆,迎江店,780.00
CSV
curl -s --noproxy '*' -X POST localhost:3001/api/v1/documents \
  -H "Authorization: Bearer $(cat /tmp/office_token.txt)" -F "file=@/tmp/sales_oct.csv"
# 预期：{"file_name":"dev/sales_oct.csv","size":247}
```

**发任务**：

```bash
curl -s --noproxy '*' -N -X POST localhost:3001/api/v1/tasks \
  -H "Authorization: Bearer $(cat /tmp/office_token.txt)" -H 'Content-Type: application/json' \
  -d '{"text":"先清洗 sales_oct.csv，再按城市汇总销售额做分析，最后生成一份月度报表","attachments":["sales_oct.csv"]}' \
  | tee /tmp/t1.ndjson >/dev/null
```

**预期（逐条对）**：

| # | 观察点 | 期望值 |
| --- | --- | --- |
| 1 | 路由 | `done` 事件 `status=multi`（复杂度 5.5 ≥ 3.0） |
| 2 | 子任务 | `status` 事件依次出现 `cleaning → analysis → report` 的 running/done，且都带 `subtask_id` |
| 3 | 结果传递 | analysis 的终答里出现 **`clean_id=c-xxxxxxxx`**（清洗产出的 ID 由上游带入，不是自己重新清洗）；report 的终答引用同一 clean_id |
| 4 | 数字对账（手算） | 上海 **4350.50**（1280.50+1420+1650）、安庆 **2580.00**（860+940+780）、合计 **6930.50** |
| 5 | 制品 | 出现 `artifact` 事件，文件 `_out/w-xxxxxxxx.md`（报表文档） |
| 6 | 终答质量 | 各子任务终答是**人话**（不再出现"已有工具结果，停止重复调用"这类护栏原文） |
| 7 | token 入账 | `done` 事件 `tokens_used` ≈ 20000~26000（非 0）；`/quota` 余额相应减少 |
| 8 | seq | 全事件 `seq` 严格递增、无重复 |

**实测样本**（2026-10-23，`tokens_used=26009`）：analysis 终答含「上海 4350.50 / 安庆 2580.00 / 合计 6930.50」，report 产出「锅圈销售月度报表（按城市汇总销售额）.md（920 字）」。

**失败判据**：analysis 反问"要分析什么"（=用户请求没进子任务）｜analysis 重新 `clean_table`（=上游结果没传）｜数字对不上（=编造或算错）。

## 3. 核心正例：同层并行（无依赖的两个子任务一起跑）

**目的**：验证「没有依赖的放在同一层一起跑」。

```bash
curl -s --noproxy '*' -N -X POST localhost:3001/api/v1/tasks \
  -H "Authorization: Bearer $(cat /tmp/office_token.txt)" -H 'Content-Type: application/json' \
  -d '{"text":"清洗 sales_oct.csv，同时查一下知识库里有没有销售相关的制度规定","attachments":["sales_oct.csv"]}' \
  | tee /tmp/t2.ndjson >/dev/null

# 只看状态事件顺序：
python3 -c "
import json
evs=[json.loads(l) for l in open('/tmp/t2.ndjson') if l.strip()]
print([(e['data'].get('agent'), e['data'].get('state')) for e in evs if e['type']=='status'])
"
```

**预期**（并行 = 两个 running 都出现后才有 done；实测顺序）：

```
[('planner','done'), ('orchestrator','running'),
 ('rag_retrieval','running'), ('data_cleaning','running'),
 ('data_cleaning','done'), ('rag_retrieval','done'),
 ('orchestrator','done')]
```

- ✅ 判据：**第 2 个 running 出现在第 1 个 done 之前**（`rag running` 在 `cleaning done` 之前）= 真并发。
- ❌ 串行会是 `running→done` 成对出现，绝无两个 running 并存。
- 补充：`rag` 子任务当前可能返回 502（RAG 侧上游 LLM 连接故障，与本迭代无关）；即使失败，也应是**如实说明**而不是编造制度条文。

## 4. 负例：上游失败要如实传递（最能防编造）

**目的**：上游没产出时，下游必须说"上游没数据"，不能自己编。

```bash
curl -s --noproxy '*' -N -X POST localhost:3001/api/v1/tasks \
  -H "Authorization: Bearer $(cat /tmp/office_token.txt)" -H 'Content-Type: application/json' \
  -d '{"text":"先清洗一份不存在的表格 nosuch.csv，再分析销售趋势，最后生成报表"}' \
  | tee /tmp/t3.ndjson >/dev/null
```

**预期**：
| 子任务 | 期望措辞（大意） |
| --- | --- |
| cleaning | 明确说"文件不存在 / 缺文件名"，不产出 clean_id |
| analysis | 明确说"**上游清洗未产出**可用数据，无法分析"；**不出现任何编造的销售数字** |
| report | 明确列出缺失项（数据源/时间范围/指标），不生成假报表 |

**失败判据**：任何一级出现具体金额/趋势结论却没有数据来源 = 编造，直接判不通过。

## 9. 验证时发现的两个真缺口（不属 p4.3，但影响真实使用）

### 9.1 配额暂停后无续跑入口
`graph.resume_task` 只有内部函数，**没有 HTTP 接口**；checkpointer 是内存 `MemorySaver`（进程重启即丢）。用户遇到"余额不足已暂停"后，前端无法续跑，只能重新提问。

### 9.2 没有管理端充值
余额耗尽后只能手工改库（本文第 0 节那条 SQL）。管理端（充值 + 用户列表）尚未实现。

> 这两条已列入"下一步"建议（P0）。
