## 二、根因 ①：planner 输入被记忆注入污染（p6.29 回归，已复现）

本地用**逐字节原文**跑 planner：`intents=['analysis','visualization']，score 2.5 → single/data_analysis`——**根本不进 rag**。
但 `_stream_task` 实际喂给 planner 的文本 = `【用户长期记忆】…` + `prepare_turn` 输出。该用户记忆里有：

> 真机验证：报销口径以财务**制度** 2026 版为准

"**制度**"是 planner.yaml 的 rag 关键词（`[查一下, 知识库, 文档里, 根据资料, 检索, 引用, 出处, 制度, 手册]`）→ rag 意图 +1 → 意计数 3、文本变长 → score 2.5→4.5 → multi + rag 子任务。本地已逐字复现（4.5 / ['analysis','rag','visualization']）。

这暴露的是**输入隔离缺失**，不是记忆内容的问题：历史摘要、近期对话、长期记忆任何一块只要含"制度/检索/手册"等词，都会劫持意图识别。历史摘要此前就存在这个隐患，p6.29 记忆注入把它变成了必现。

**修法（P0）**：意图识别/复杂度打分只看【本轮问题】原文。`TaskState` 增加 `raw_text`（routes 传入原文），`planner_node` 用 `raw_text` 跑 plan/decide/decompose；注入块照旧给 Agent 上下文（brain 的 task 不变）。补回归测试：含"制度"记忆 + 本轮无 rag 词 → 不进 rag。

## 三、根因 ②：能力缺口——用户要的三件事，现在的工具池一件都做不到

| 用户要的 | 现状 | 缺口 |
|---|---|---|
| 明细表格 csv/excel（城市/用户/线上线下/支付方式/平台…） | query_orders 只能 `group_by` 聚合、limit 50、**明确不返回手机号/姓名** | 没有"按筛选导出明细行到文件"的工具 |
| 缺字段的列不出（如支付方式） | guoquan_orders 表**确实没有支付方式列**（只有 pay_time/pay_amount） | 工具需要把 `omitted_fields` 如实返回，由 Agent 说明"表里没有支付方式，该列未生成" |
| 文档内嵌销售趋势图表 | write_document 只写 md/docx 且"不画图"；render_chart 只吃 clean_id | ① 图表工具吃不到 DB 查询结果；② 文档工具不能嵌图 |

**修法（P1，能力补齐三件套）**：
1. **`export_orders` 工具**（data_analysis/report_generation 可见）：按现有筛选参数（date/city/store/channel/status…）导明细行 → csv（xlsx 可后补）落到 `_out/`，返回 `file_name + 行数 + 列名清单 + omitted_fields`（如 `["支付方式"]`）。列映射：城市（查询参数）、门店 store_name、用户 receiver_phone（**脱敏** 138****1234，维持隐私红线）、是否线上（order_channel+fulfillment_type 推导：门店自提/门店扫码=线下，外卖/小程序=线上）、平台 order_channel、销售金额 pay_amount。**不存在的字段→整列省略**，并在返回里说明。
2. **图表数据链**：`export_orders` 返回 `export_id`（与 clean_id 同构），`render_chart` 放宽为同时接受 `clean_id | export_id`——销售趋势=按月 group 的 export 结果画 line/area，复用现有画图管线。
3. **文档嵌图**：`write_document` 增加 `image_file` 可选参数——md 用 `![](w-xxx.svg)` 相对引用（同目录已有文件），docx 用 python-docx `add_picture` 嵌入。

## 四、拆分方案：如果我来做

**我读出的意图**（与系统对比）：
- 用户真实意图是**两步串行任务**：① 取数并导出明细表（data_analysis：上海、2026-01-01～今、明细行、指定列、缺列省略）；② 基于该表写销售总结文档（report_generation：**内嵌**趋势图表 + 销售建议）。
- 系统判定 `['analysis','rag','visualization']`：rag=误触发（bug）；**visualization 拆成独立子任务是映射错误**——"文档中有图表"是文档的内嵌产物，不是独立交付物。独立拆出去必然失败（图需要数据文件，而子任务间只传文本摘要），这次 viz 子任务"没调工具如实认怂"就是证据。

**我的拆法（修好 P0 后）**：
```
multi（2 子任务）或 single 直跑皆可；multi 版：
  s1 data_analysis：export_orders(上海, 2026-01-01~今天) → 明细 csv + export_id
     └ 依赖传递要带【数据资产】：file_name / export_id / 行数 / omitted_fields（不只文本摘要）
  s2 report_generation：render_chart(export_id, line, x=月份, y=sum_pay) → 趋势图
     → write_document(销售总结, content=分析+建议, image_file=趋势图)
rag：不进 DAG（本任务无制度/口径问题；planner 修复后自然不会进）
```
若走 single：data_analysis 一个 Agent 顺序调 export_orders → render_chart → write_document，效果等价且少一次汇总拼接。**建议 single 优先**（这条链是严格串行、单一主线，multi 只在子任务可并行时才有收益）。

**P1 配套小修**：multi 汇总不再原样 `join(子任务终答)`——加一步汇总脑（或复用 synthesize 机制）把各子任务产出重写成"最终交付物说明（文件清单+核心结论）"，消除表格重复展示；子任务间传递增加 `assets`（file_name/export_id/clean_id）字段，与文本摘要并列。
