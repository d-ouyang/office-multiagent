# 手动验证 · p6.30 销售链路测试用例（2026-10-23）

> 用法：8080 登录 dev/Office@2026，逐条原样输入。每条标注了**预期意图路由 / 工具调用 / 交付物 / 终答形态**。
> 不符预期时把「实际 vs 预期」+ run_id 给我，按「排查点」继续修。
> 跑完一条等 done 再跑下一条（避免并发流互相干扰）。每条约消耗 2K~35K tokens。

---

## A 组：主链路（p6.30 新能力）

### A1 明细表格 + 总结文档 + 图表（主用例，即复盘那条）
**输入**
```
拿到上海今年1月到现在的所有订单，形成表格，表格里要包含销售金额、门店、用户、是否是线上还是线下、支付方式、平台等信息。然后根据这个表格写一份销售总结文档，文档中最好有图表展示销售趋势，并给出销售建议。
```
**预期**
- 意图：`['analysis']`，复杂度 1.0，**single / data_analysis**（过程面板第一行"识别意图"）；
- 工具：`export_orders` 1 次（city=上海、fields 含你点名的列）→ `query_orders` 0~2 次（补分析口径，属合理）→ `render_chart` ≥1 次 → `write_document` 1 次（带 image_file）；
- 交付物：明细表文件（csv/xlsx）+ 总结文档（内嵌图表）；**支付方式列不存在 → 整列省略且终答里如实说明**；
- 终答：核心结论 + 交付清单，**没有整张表重复贴出**；
- 用户列出现的是脱敏手机号（138\*\*\*\*0000 形态）。
- 排查点：若进 rag → planner 隔离失效；若拆 multi → 折叠失效；若图表失败 → 看 render_chart 的 observation（xlsx/csv 读回问题）。

### A2 换个说法（时间列 + 趋势折线）
**输入**
```
导出上海 2025 年 3 月到 5 月的订单明细成 csv，要包含下单时间、门店、平台、销售金额这几列，然后按月汇总画一张销售趋势折线图，图片单独给我。
```
**预期**
- single / data_analysis；`export_orders`(format=csv，fields 含 下单时间) → `render_chart`(export_id, chart=line, x=下单时间 或按月) ；
- 交付：csv + 一张折线图 svg/png；不生成文档（用户没要文档，write_document 不应被调用）。
- 排查点：若模型说"明细表没有时间列画不了" → 说明 fields 里没带下单时间（工具描述提醒失效）。

### A3 城市范围 + 状态排除
**输入**
```
把安庆今年所有的订单导出来，不要已退款和已取消的，表格里要有门店、销售金额、履约方式、下单时间。
```
**预期**
- `export_orders` 带 city=安庆、exclude_status（两个状态可写成「已退款、已取消」或列表），交付 csv/xlsx；
- omitted 为空（这些列都存在）；终答给出行数与合计金额（合计为模型自算 → 可能触发"结果校验"软提示，属正常，提示文案是"请注意核对"不是报错）。

### A4 行数上限 / 截断
**输入**
```
导出 2024-01-01 到 2026-12-31 全部城市的订单明细，要所有订单一行不落。
```
**预期**
- 导出成功但若超过 5000 行（当前库约 3 年数据量，取决于种子）→ 返回 truncated=true，终答**如实说明已截断**，不会谎称"全部导出"。
- 排查点：若谎称全部 → 违反如实纪律，需要补提示词。

### A5 城市不在样例数据里
**输入**
```
导出北京的订单明细。
```
**预期**
- 会调用 `export_orders`，city=北京（按门店地址包含匹配，**不再**因为不在「上海、安庆」名单里被拒绝）；
- 当前库若没有北京门店，返回「该筛选范围内没有订单」→ 终答如实说没有，**不编造北京数据**；
- 库里若已有北京市地址的订单，应导出这些行，城市列写「北京」。

## B 组：老能力回归（确认没被改坏）

### B1 纯聚合统计（query_orders 路径）
**输入**
```
统计上海 2025 年 10 月各渠道的订单数和销售金额。
```
**预期**
- single / data_analysis；`query_orders`(group_by=order_channel) 1 次；**不调用 export_orders**（用户没要文件）；终答是简短统计结论。

### B2 销售报表（sales_report 路径）
**输入**
```
生成 2025 年 10 月的销售报表，按门店分组，指标用实付金额，并给出销售建议。
```
**预期**
- `sales_report` 1 次（date_from/date_to/metric=sum_pay/group_by=store_name）→ 直接写分析；不再调 sales_report。

### B3 上传表格清洗 + 画图（clean_table 路径，确认 clean_id 入口没坏）
**输入**：先上传一份 csv（如 sales_oct.csv），然后：
```
把 sales_oct.csv 清洗一下，然后按门店画一张销售金额柱状图。
```
**预期**
- `clean_table` → `render_chart`(clean_id=c-…) 正常出图（p6.30 后仍支持 c- 入口）。

### B4 制度问答（rag 正例——确认 rag 没被"误伤"）
**输入**
```
查一下知识库里差旅报销的制度是怎么规定的。
```
**预期**
- 意图含 rag（这条**应该**进 rag）；`rag_retrieve` ≤2 次；知识库没覆盖就如实说"未检索到"。
- 排查点：若这条也不进 rag → 折叠/隔离改过头了（不应发生：本轮原文有"查一下知识库"）。

### B5 记忆（p6.29 回归）
**输入**：先说
```
记住一件事：我看报表喜欢先看环比变化。
```
再新开会话说：
```
不调用任何工具，直接回答：我之前让你记住的偏好是什么？
```
**预期**
- 第一条 → `remember` 落库（source=agent）；第二条 → 不调工具直接答出"环比"（每轮注入生效）。

## C 组：多 Agent / 汇总重写（p6.30 P1-c）

### C1 真·多步复杂任务（应走 multi）
**输入**
```
先把我上传的 sales_oct.csv 清洗干净，然后分析各门店的销量和金额分布，最后生成一份带图表的 xlsx 报表文件。
```
**预期**
- 复杂度 ≥3 → multi；子任务 = cleaning → analysis（visualization 折进 analysis，**没有独立 viz 子任务**）；
- **汇总答复 = "核心结论 + 交付文件清单"，不是把各子任务终答整段重复**（对照：p6.29 之前 5 张表贴两遍的问题）；
- 交付：清洗表 + 图表 + （write_document 只产 md/docx，**不会**产 xlsx——若用户坚持要 xlsx 报表，终答应如实说明"当前只支持 md/docx 文档"，这是既有边界，不是 bug）。
- 排查点：若汇总仍重复贴表 → 汇总脑失败回落了拼接（看 WARNING 日志）。

### C2 无工具闲聊（结果校验器 skip 路径）
**输入**
```
用一句话介绍你自己。
```
**预期**
- 不调任何工具，直接回答；**无 result_validator 事件**（没调工具 → 跳过对账）。

## D 组：观察点速查表

| 看哪里 | 怎么看 | 说明 |
