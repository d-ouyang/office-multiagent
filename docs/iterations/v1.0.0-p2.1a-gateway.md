# 迭代总结 · v1.0.0-p2.1a — NestJS 网关容器（任务 4/5/6 的网关侧）

> 对应计划：PLAN-1.0.0.md Phase 2 / v1.0.0-p2.1a（网关：认证 + NDJSON 透传 + 内部调用）。Tag：`v1.0.0-p2.1a`。前端可视化组件留到 p2.1b。

## 1. 目标
按设计文档 §13.3 + RAG 实战蓝本，落地 **NestJS 网关容器**：全局 JWT 鉴权（passport-jwt，与后端 PyJWT 共用 `jwt_secret`）、`/api/v1/*` NDJSON 流式透传（不缓冲/不重排）、网关→后端内部调用（`node:http` + `X-Internal-Token`）。接在 backend 之前，成为统一入口。

## 2. 做了什么
- `gateway/`：NestJS 10 脚手架（`package.json` 锁定与 RAG 同源的稳定版、`tsconfig`/`nest-cli`/多阶段 `Dockerfile`/`.dockerignore`）。
- `config/configuration.ts`：env 驱动，`jwtSecret`/`internalToken` **生产缺失即启动失败**（fail-closed）；`backendUrl` 默认 `127.0.0.1`（避 IPv6 ::1 坑）。
- 鉴权：`auth/`（`@Public()` 装饰器、`JwtStrategy` passport-jwt 验签、`JwtAuthGuard` 全局守卫——默认保护一切，白名单放行，缺/错/过期一律 401）。
- `internal/`：`InternalAuthClient` 用 `node:http`（不读 HTTP_PROXY）带 `X-Internal-Token` 调后端 `/api/v1/internal/auth/ping`；`/api/internal/ping` 自检路由。
- `proxy/proxy.controller.ts`（核心）：`createProxyMiddleware`，`selfHandleResponse:false`（NDJSON 不缓冲）+ `Accept-Encoding:identity` + `fixRequestBody` 置于所有 `setHeader` 之后；代理注册为 **Controller 通配路由**（守卫先于转发）；白名单路径声明在通配之前。
- `main.ts`：bodyParser 手动挂、CORS 在守卫前、trust proxy  opt-in、进程级异常兜底（无状态转发，可用性优先）。
- 接线：`docker-compose.yml` 加 `gateway` 服务；`frontend/nginx.conf` 反代 `/api` → `gateway:3000`；根 `.env.example` + `gateway/.env.example` 补全；`.gitignore` 加 Node 产物。

## 3. 否掉的方案（最值钱）
- **不用 `app.use(createProxyMiddleware)`**：Express 中间件跑在 Nest 守卫之前 → 「没带 token 也转发成功」且日志正常，极难发现。必须注册成 Controller 路由，走到 handler 才转发。
- **`fixRequestBody` 顺序**：它 end 掉 proxyReq，此后 setHeader 抛 `ERR_HTTP_HEADERS_SENT` 且无人 catch，一个 POST 打挂进程 → 所有 setHeader 必须在它之前，整段包 try/catch。
- **网关不自己判密码 / 不做登录签发**：登录态真相源与签发留到用户模型落地（后续阶段）；当前守卫先就位，敏感路径 fail-closed，只读脚手架（health/models/demo）放行。
- **不提交 `node_modules`/`package-lock.json`**：`.gitignore` 屏蔽；Dockerfile `npm install`（国内镜像）构建。lockfile 固化留作后续硬化（避免把 npmmirror URL 锁进仓库）。

## 4. 验证（真实跑通，非跳过）
- `tsc --noEmit` 通过（修了两处：回调里 `req` 是 `http.IncomingMessage`，`originalUrl` 需 cast 成 express `Request`）。
- `jest`：**9 passed / 2 suites**。
  - `configuration.spec.ts`：生产缺密钥抛错 / 开发随机生成 / 解析 origins。
  - `proxy.e2e.spec.ts`（起假后端流式吐 NDJSON）：白名单 `/api/v1/demo/stream` 免 token 且 NDJSON 逐行透传有序（`[thinking_delta,tool_call_start,done]`、seq `[1,2,3]`）；`/api/v1/models` 透传；非白名单 `/api/v1/tasks` 无 token→401；带有效 JWT→放行转发；`/api/internal/ping` 走 node:http 打通后端内部探活。
- `docker compose config` 通过；`node_modules` 确认被 gitignore。
- ⏸️ 未跑 `docker compose up` 全栈（点5 谨慎）；未对真实后端跑 e2e（假后端已覆盖协议层）。

- 未做网关侧限流（RAG 有 throttler，office 后续按需加）。
- `package-lock.json` 未固化（见 §3）；生产需把 backend 8000 收进内网（当前 compose 仍宿主映射，dev 便留）。
