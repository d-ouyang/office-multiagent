# 迭代总结 · v1.0.0-p6.13 — 对话体验、账号与按用户读文件

> 把 p6.12c 之后已在本地跑通、尚未入库的一批收成一个版本。Tag：`v1.0.0-p6.13`。

## 1. 目标
输入、回复、个人中心和附件预览按现在的使用方式落地；改密后旧登录态失效；模型读上传文件时不用用户自己拼 `用户名/`。

## 2. 做了什么
- 输入条使用 PromptBar，保留发送、停止、上传、模型选择。力度固定三档（低 / 高 / 最大），按模型的 `reasoning_efforts` 折叠后再写入请求；没有该参数的模型不传这个字段。
- 侧栏展示简介和版本。用户消息在悬停时显示时间、编辑和复制。回复下方固定显示复制、赞、踩、用量、模型、时间和耗时。赞踩只留在浏览器里。
- 个人中心展示登录名、工号、角色、剩余额度、本月用量和累计用量。剩余额度进入消耗明细，列出结算时间、模型和用量。退出登录与上面的行对齐，点击后需确认。
- 网关改密校验旧密码、长度和「与旧密码不同」，成功后 `token_version` 加一，并签发新 token。后端验签时比对版本，旧 token 不再识别。
- 已发送消息在正文下方显示「附带文件」。预览读取服务器上该用户目录中的文件。
- `read_document` 的根目录改为当前用户的上传目录。文件名和 `用户名/文件名` 都能读到；越出该目录的路径拒绝。

## 3. 否掉的方案
- 不把上传目录拆成开发目录和线上目录。`dev` 是登录用户名。
- 不要求模型或用户手写 `dev/文件名`。提示词只给文件名，查找目录由服务按登录身份决定。
- 不在这一版接入对象存储。文件仍在 `data/upload/<用户名>/`。
- 力度不做四档。界面三档；模型只有两档时，前两档并到较低档，只有「最大」对应最高档。

## 4. 验证
- 后端：pytest 174 passed / 3 skipped（迁移护栏在容器内需能读到仓库的 `db/init.sql`）。
- 前端：vitest 56 passed。
- 网关：`auth.controller.spec` 8 passed，含改密后签发新 token。
- 浏览器核对过：消耗明细能列出时间和模型；退出需确认；PDF 预览弹窗铺满当前窗口。

## 5. 风险
- 历史回复若对不上账本，用量和模型可能配到相邻轮次。
- 赞踩刷新后消失。
- 预览和读取仍只覆盖 md、txt、pdf。docx、csv、xlsx、json 留到下一步。
