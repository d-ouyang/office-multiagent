# 迭代总结 · v1.0.0-p1.2a — 连接层加固（任务 1）

> 对应计划：PLAN-1.0.0.md Phase 1 / v1.0.0-p1.2a（任务 1「连接层加固」）。Tag：`v1.0.0-p1.2a`。

## 1. 目标
把三件套客户端从"模块级直接实例化"改成**可注入的懒创建工厂**：连接池 / 超时参数走配置，启动期按退避重试预热，mysql/redis 未就绪时**降级运行而非崩溃**，让 backend 在 compose 起停顺序与网络抖动下不崩、可自愈。

## 2. 做了什么
- `core/config.py`：新增 `mysql_pool_size`/`mysql_max_overflow`/`mysql_pool_timeout`、`redis_socket_timeout`/`redis_socket_connect_timeout`/`redis_health_check_interval`、`chroma_timeout`、`connect_max_retries`/`connect_retry_backoff`。
- `core/db.py`：引擎改懒创建 `get_engine()`，池参数走配置，`pool_pre_ping=True`（抗 DB 瞬断）+ `pool_recycle=3600`。
- `core/redis_client.py`：改懒创建 `get_redis()`，socket 超时 / `health_check_interval` 走配置。
- `core/chroma_client.py`：保持懒加载（本就降级不致命），未改逻辑。
- 新增 `core/startup.py`：`_retry_ping`（线性退避）+ `warmup_connections()` 汇总三件套探活。
- `main.py`：加 `lifespan`，启动时 `warmup`，未全绿则 `error` 日志降级运行（不 kill 进程）；版本号 bump `1.0.0-p1.2a`。
- `.env.example` 补全新变量；新增 `backend/tests/test_connection.py`。

## 3. 否掉的方案（最值钱）
- **否掉「启动即 kill 容器」**：mysql/redis 未就绪时退出进程 → compose 反复重启、丢失现场、日志刷屏，且共享中间件被别的服务重启时会误伤。改为**降级运行 + `/health` 暴露 + 逐请求自愈**（`pool_pre_ping`/`health_check_interval`）。
- **否掉模块级直接实例化连接句柄**：改为懒创建工厂 `get_engine()`/`get_redis()`，便于测试注入，也为后续仓储层按 FastAPI `Depends` 取用留口。
- **顺带修一个真实 bug**：`log_duration` 用 `name` 作 log-extra 键，撞 `LogRecord.name` 保留属性直接 `KeyError`（`test_connection` 跑到 warmup 才暴露）→ 改名 `span`，并加回归断言。

## 4. 验证
- `pytest backend/tests`：**17 passed / 3 skipped**（3 个集成测试因 `OFFICE_INTEGRATION!=1` 默认 skip）。
- 新增覆盖：引擎单例 + `pool_pre_ping` 生效、redis 单例 + `socket_timeout` 生效、重试语义（首发即成功 / 耗尽后返回 detail）、`warmup_connections` 在缺服务时返回报告而不抛异常。
- `test_logging` 加 `log_duration` 回归断言（防再撞保留字）。
- `py_compile` 全绿。

## 5. 风险 / 已知遗留
- `chroma_client` 未加显式超时参数（chromadb `HttpClient` 的 settings 较繁琐，留待真正调用检索时再细化）。
- 全栈实跑（`docker compose up`）未自动跑（点5 谨慎，交显式执行或沙箱代跑）。
