# v1.0.0-p6.41 — 引入 Skill 能力层（P1）

新分支 `cursor/skill-layer-p1`（基于 master）。**只新增，不动运行时**：`router.py` / `agents.py` / `orchestrator.py` 一行未改。

## 为什么要这一层

原来「业务能力」和「原子工具」混在一起：`tools_write.py` / `tools_export.py` / `tools_rag.py` 既当工具又当能力，`agents.yaml` 里每个 AgentSpec 直接列十几个工具白名单。加一个业务域就得改白名单，能力逻辑散落在 tools 文件里，Agent 之间也难共享。

拆成三层：**Tool**（原子函数）/ **Skill**（能力包 = 声明 + 指令 + 一组工具 + 记忆权限）/ **Agent**（运行时实体）。Agent 只需声明"我会用哪些 skill"，工具从 Agent 视角隐身，成为 skill 的实现细节。

这也补上了参考架构里缺失的「Agent Skills（能力管理、任务路由）」组件与 ⑧ 加载 Skill 上下文。

## 落了什么

- `backend/app/skills/base.py`：`SkillSpec` / `Trigger` / `MemoryAccess` / `SkillContext` + `parse_skill`。
  `enabled` **缺省 false（fail-closed）**；`matches()` 走 intent 优先、关键词兜底。
- `backend/app/skills/registry.py`：`SkillRegistry`——扫描 `skills/<name>/spec.yaml` + `prompt.md`
  （单个坏 spec 只跳过并记 warning，不炸整表）、`restrict_tools()` 按白名单裁剪受限工具集、
  `match()` / `prompt_for()`。`load_skill_registry()` **不缓存**，与 agents.yaml 口径一致。
- `backend/app/skills/doc_writing/`：示例能力包。`spec.yaml` 声明 tools=write_document/render_chart/clean_table；
  `prompt.md` 写指令；`run.py` 做 format 归一化与白名单校验、title/content 必填校验，
  然后**委托**给受限工具集里的 `write_document`——不重新实现落盘逻辑。
- `backend/app/core/config.py`：新增 `skills_dir`（留空自动定位 `backend/app/skills`；容器候选 `/app/app/skills`）。

## 三条链路怎么验的

`backend/tests/test_skills.py` 10 例全过：spec 加载、prompt 注入、受限工具集
（未声明的 `db_query` 对该 skill 不可见）、声明未注册工具则跳过、未启用不可路由但已加载、
关键词+intent 匹配、未知 skill 返回 None、run 护栏拦截非法 format、缺工具报 `CAPABILITY_MISSING`、
真实委托落盘 PDF。

## 纪律

- fail-closed：所有 spec 默认 `enabled: false`，上线一个开一个；未知 skill 一律回落 `general`。
- skill 只声明工具名，不持有工具实现；`run.py` 失败返回 `{"ok": False, "error": ...}` 不抛异常。
- 规划中的路径（`orchestration/tools/`、`app/memory/`）当前**不存在**，别按它找文件。
