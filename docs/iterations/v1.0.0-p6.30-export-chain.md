## P0：planner 输入隔离（修复"乱进 RAG"）

- **根因复现**：`_stream_task` 把【用户长期记忆】块（含"财务**制度**"）拼进 effective_text
  才给 planner，"制度"命中 rag 关键词 → 2.5/single 被劫持成 4.5/multi+rag 子任务。
- **修复**：`TaskState.raw_text`（本轮用户原文）；`planner_node` 只用 raw_text 跑
  plan/decide/decompose；注入块照旧给 Agent 上下文（brain 的 task 不变）。
  routes 传 `raw_text=text`（原文）。回归测试：注入块含"制度"+原文干净 → 不进 rag。

## 折叠规则（修复"图表被拆成独立子任务"）

- `planner.plan()` 新增折叠：文本同时命中 analysis/report/cleaning 与 visualization 时，
  **visualization 折进主意图**（这些 Agent 自带 render_chart，"文档中带图表"是内嵌产物
  而非独立交付物；独立拆出去必然拿不到数据文件——真跑事故 viz 子任务零工具调用）。
- 单独要图（"把我的表画成饼图"）仍走 visualization Agent。配置开关 `fold_visualization: true`。
- 效果：用户原任务文本 → `['analysis']` / score 1.0 → **single data_analysis 直跑**。

## P1-a：export_orders 明细导出工具

`orchestration/tools_export.py`。与 query_orders 的分工：聚合统计 vs 明细交付物，两份契约不互相膨胀。

- 参数：date_from/date_to（必填）+ city/store_name/order_status/exclude_status/order_channel/
  order_type/fulfillment_type/member_level + **fields**（要保留的列名列表）+ format（csv/xlsx）。
- 字段映射（_FIELD_SPECS）：下单时间/订单号/城市（由 store_address 推导）/门店/
  **用户（手机号脱敏 138\*\*\*\*0000，原始号码不落盘不进上下文）**/是否线上（渠道推导：
  门店扫码→线下，其余→线上，口径写入 derived_note）/平台/销售金额/订单金额/优惠/退款/
  订单状态/订单类型/履约方式/会员等级/商品件数。
- **缺字段整列省略**（用户点单）："支付方式"等表里没有的字段→ omitted 如实说明；认不出的
  字段名同样省略不报错。
- 落盘 `_out/e-<16hex>.csv|xlsx`（utf-8-sig，Excel 直开）+ asset 落库；行数上限
  `EXPORT_ORDERS_MAX_ROWS`（默认 5000，超限截断如实标注）。
- 白名单：general / data_analysis / report_generation；query_orders 描述补
  「要明细表格改用 export_orders」；data_analysis 提示词补整条链路指引。

## P1-b：图表数据链 + 文档嵌图

- `render_chart` 接受 **export_id（e-）** 与 clean_id（c-）双入口——明细导出后直接画图，
  不必再 clean_table；同时产出 **png**（docx 嵌图需要位图，svg 嵌不进 docx）。
  真跑回归：模型选 xlsx 导出时 load_export 只会读 csv → "找不到导出表"（真机抓到），
  已修：csv/xlsx 双格式读回，xlsx 数值单元格统一转字符串。
- `write_document` 新增 **image_file** 参数：校验必须是本用户 `_out/g-*.(svg|png)` 且存在；
  md 用相对引用嵌入，docx 用 python-docx add_picture 嵌 png（真机验证：zip media 里确有
  16.6KB 的 image1.png）。
- 预览白名单放宽：`_OUT_FILE` 正则 `^[weg]-…\.(md|docx|svg|png|csv|xlsx)$`（导出表与 png
  可经 /documents/content 预览下载）。
