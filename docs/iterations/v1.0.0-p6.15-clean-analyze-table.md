# 迭代总结 · v1.0.0-p6.15 — 上传表格先清洗再分析

> Tag：`v1.0.0-p6.15`。

## 1. 目标
上传的表先变成一份可引用的清洗结果，再在这份结果上做筛选、分组和汇总。原始文件保持不动。

## 2. 做了什么
- `clean_table` 接受 csv、xlsx 和对象数组 json。去掉全空行、全空列、重复出现的表头行、完全相同的行。单元格去掉首尾空白，并把 `null`、`N/A`、`无`、`-` 视为空。
- 传入 `key_columns` 时，这些列为空的行从结果中剔除，并单独计数。没传就不猜关键列，只列出每列缺了多少。
- 不把缺失填成平均数，不因为数值特别大或特别小而删行。不能转成数字的格子在 `sum` / `mean` / `min` / `max` 里跳过；一整组都无法换算时，汇总值是空，不是 0。
- 清洗结果记为 `clean_id`。`analyze_table` 只认这个编号，支持过滤、分组，以及 count、sum、mean、min、max、count_distinct。
- 通用、分析、清洗、报表这几个 Agent 都能调用这两个工具。公司业务库仍用 `db_query`。

## 3. 否掉的方案
- 不让分析工具直接读原始 csv。否则模型会绕过清洗，把脏行算进去。
- 不自动挑选关键列。列名对错会把不该删的行删掉。
- 不在清洗阶段把「待定」换成 0。那会把无法汇总说成金额是 0。

## 4. 验证
- `tests/test_tools_table.py` 6 passed：空行、重复行、重复表头、缺关键列、空列、xlsx 分组求和、非数字跳过、拒绝原始文件名和路径穿越。
- 与 `test_agents.py`、`test_tools_doc.py` 一起跑过，共 30 passed。
- 容器内用样例表核对过：上海金额求和为 10，北京「待定」不记成 0。

## 5. 风险
- 一次过滤只适合模型按工具参数传入。复杂条件要多次调用。
- 多 Agent 拆开时，后一个子任务不会自动拿到前一个的 `clean_id`。同一轮里由同一个 Agent 先清洗再分析才接得上。
- xlsx 使用 data_only，没有缓存值的公式格会是空的。
