# v1.0.0-p4.3d — 子任务带上用户请求 + 护栏停止后强制收尾（真跑验证驱动的两处修复）

**类型**：修复（p4.3 收尾）｜ **日期**：2026-10-23

## 背景

按 p4.3 计划做完 a/b/c 后，写手动验证用例时用真模型实跑，暴露两处**功能可用性**问题（不是结构问题）：

1. **子任务只拿到意图关键词，丢了用户原话**：`compose_subtask_text` 只拼 `intent + 上游摘要`，真跑原话「任务描述里只有'analysis 任务'四个字，没有说明要分析什么」→ 多 Agent 任务只能反问，等于没干活。
2. **护栏停止把内部提示原文当终答**：模型重复调用同一工具时，p6.7 护栏强制停止，但 final 是「已有工具结果，停止重复调用…上次观察：…」这类机器话，用户直接看到。

## 交付内容

- **`compose_subtask_text` 增加 `request_text`**（orchestrator.py）：子任务文本 = 用户完整请求（截断 6000 字）+ 本步分工（"只完成与 X 相关的部分，不要越界重复"）+ 本步任务 + 上游结果 + 收尾纪律；无 request_text 时保持 p4.1 原样（向后兼容，单测锁定）。
- **`run_react` 增加 `synthesize` 回调**（react.py）：三条护栏停止路径（重复调用 / 连续无效工具名 / 超步数）在被拦下时，用回调把已有观察收尾成面向用户的结论；回调异常则如实回落护栏原文（不阻断、不编造）。
- **`spec_agent_runner` 提供 synthesize**（graph.py）：用**空工具池**脑（协议里没有工具，只能给自然语言终答）基于历史观察写收尾；这次收尾的 token 用量并入 `res.tokens_used`，账不漏。
- **测试**：+7（request 拼装/截断/与上游共存、synthesize 三路径、synthesize 失败回落）。
