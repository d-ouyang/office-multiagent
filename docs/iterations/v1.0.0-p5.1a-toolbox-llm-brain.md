# 迭代总结 · v1.0.0-p5.1a — 真实工具层 + LLM 客户端 + Brain 接入（Phase 5 首步）

> 对应 PLAN Phase 5 / v1.0.0-p5.1a。Tag：`v1.0.0-p5.1a`。

## 1. 目标
办公能力池第一批：**两类真实工具**（db_query 只读查库 / rag_retrieve 检索知识库）+ **LLM 客户端**
（OpenAI 兼容、读 models.yaml 注册表）+ **Brain 接入**（LlmBrain 实现 p4.1 的 Brain 协议，
配置驱动回落 StubBrain），并把真实 token 用量接进 §十四 的两段式结算。

## 2. 做了什么
- `core/llm.py`：`chat()` 走 `/chat/completions`；模型/provider/密钥全部来自 `config/models.yaml`
  （`load_registry` 的 ModelEntry/ProviderEntry），密钥按 api_key_env 从 Settings→环境变量两级取；
  未配置抛 `LlmNotConfigured`（fail-closed）；`LlmResult` 带 usage（§十四 数据源）；MockTransport 可注入。
- `orchestration/tools_db.py`：`db_query` 硬护栏——单条 SELECT/WITH、禁分号、**词边界**拦写关键字
  （不误杀 created_at/update_time 列名）、强制 LIMIT + 硬截断；engine=None 如实"数据库不可用"。
- `orchestration/tools_rag.py`：`rag_retrieve` 走 RAG `POST /api/v1/qa/ask`，带 `X-Internal-Auth`
  （office 域密钥，rag p4.11 认）+ `X-Username`；失败抛错→ToolRegistry 转结构化如实告知。
- `orchestration/agents.py`：`build_default_registry(engine)` 装配默认工具池（未注册能力仍走
  CAPABILITY_MISSING，§四.5）。
- `orchestration/brain.py`：`LlmBrain`（ReAct JSON 决策；坏输出/LLM 不可用→**如实停止不编造**；
  `usage` 逐步累计）；`make_brain()` 配置驱动——密钥就绪→LlmBrain，否则回落 StubBrain。
- `graph.py`：single_node 用 `make_brain`；`tokens_used` 进 state；`settle` 用**真实用量**
  （StubBrain 基线 0，测试行为不变）。ToolRegistry 增 description（供 Brain 提示词）。

## 3. 否掉的方案（最值钱）
- **multi 子任务暂不接 LLM**：先 single 走真 Brain，multi 子任务仍 StubBrain——成本/延迟可控，
  p5.1b 结合各 Agent 提示词再接。
- **不做 lru_cache**：`resolve_model` 每次读注册表（毫秒级），换测试隔离干净（缓存会让
  monkeypatch key 的测试互相污染）。
- **rag_retrieve 借道 qa/ask**：有会话记录副作用，先接受（轨迹可查）；后续让 RAG 加 retrieve-only
  端点再切。
- **不擅自搬运用户其他项目的 API key**：真 LLM smoke 留给用户本机配 key 后验证（密钥治理纪律）。

## 4. 验证
- `pytest backend/tests`：**95 passed / 3 skipped**（新增 30：llm 6 / tools_db 12 / tools_rag 4 / brain 8）。
- **真实 RAG 工具 smoke**（非 mock）：`rag_retrieve` → 本机 RAG FastAPI → `route=rag_qa`，链路真通。
- 真 LLM 调用未跑（本机 office .env 无 key，见 §3）；测试环境下 make_brain 回落 StubBrain，
  全部既有行为（含 token 中断/续跑、/tasks NDJSON）不回归。
- 过程修 2 处：load_registry 返回 pydantic 模型（非 dict）→ 改属性访问；venv 漏装 alembic。

## 5. 风险 / 已知遗留
- 真 LLM 决策质量（会否不调工具/坏输出率）待本机配 `DEEPSEEK_API_KEY` 后真跑验证。
- db_query 真实 MySQL 调用待本机 compose 起库后验证（护栏已 SQLite 全测）。
- rag_retrieve 会话副作用；文档解析等重工具、multi 子任务 LLM、6 个 Agent 提示词化 → p5.1b。
