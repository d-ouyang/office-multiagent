# 迭代总结 · v1.0.0-p6.14 — 读取 docx、csv、xlsx、json

> Tag：`v1.0.0-p6.14`。扫描件和图片仍见 `docs/BACKLOG-能力扩展.md`。

## 1. 目标
让 `read_document` 能读 Word、表格和 JSON，同时避免把整张表塞进上下文。

## 2. 做了什么
- 阅读器仍是一个工具。新增 `.docx`、`.csv`、`.xlsx`、`.json`，上传白名单与工具白名单共用同一份后缀。
- csv / xlsx / docx 里的表：列出表头、数据行数，最多给出前 20 行。超过 20 行时写明「共 N 行，这里只给出前 20 行」。
- json 解析成功则格式化输出；解析失败则说明不是合法 JSON，并附上原文。
- 预览 docx、xlsx、csv、json 时返回抽出的文本。pdf、md、txt 仍按原文件打开。
- 文本按 utf-8 读取，解不开再按 gbk。

## 3. 否掉的方案
- 不拆成 `read_csv`、`read_docx` 等多个工具。模型只传文件名，后缀由程序判断。
- 不在这一步做清洗。空行、重复行留给后面的 `clean_table`。
- 不把 xlsx、docx 的二进制交给预览框。页面上看的是抽出的文本。
- 不做扫描件 OCR，也不把图片交给视觉模型。

## 4. 验证
- 后端：`test_tools_doc.py` 与 `test_documents.py` 共 27 passed。覆盖 25 行 csv 只给出前 20 行、json 合法与非法、docx 段落加表格、xlsx 工作表，以及上传 csv 后预览含表头。

## 5. 风险
- xlsx 用 data_only，没有缓存计算结果的公式格会是空的。
- 超过 20 行的明细不在这一次上下文里。问某一行时，当前工具给不出第 21 行以后的内容。
- gbk 兜底可能把损坏的 utf-8 误读成另一种中文。优先严格按 utf-8 解码，失败才用 gbk。

## 6. 下一步
扫描件和图片的方案仍在待办。其后是 `clean_table`，分析工具只接受清洗后的表。
