# v1.0.0-p4.3 — DAG 结果传递 + 层内并行 + multi token 汇总（总结）

**类型**：功能（Phase 4 补齐，p4.1 遗留项落地）｜ **日期**：2026-10-23
**分刀**：p4.3a（结果传递）→ p4.3b（层内并行 + seq 线程安全）→ p4.3c（token 汇总 + 并行度配置）

## 起因

用户在 cursor 会话里看到下一步是「把有依赖的子任务接上一步的结果，没有依赖的放在同一层一起跑」。定位为 p4.1 明确遗留项（`orchestrator.py` 注释「并行化留作后续」+ 设计文档 §四.3「支持串行/并行后汇总」）。实读代码后发现比"并行"多两个缺口，一并修复。

## 三个缺口 → 三刀

| 缺口（修复前） | 修复（分刀） |
| --- | --- |
| 依赖边只决定顺序，上游产出对下游不可见（子任务文本只有 intent） | p4.3a：`run_dag` 透传直接上游 `AgentResult`；`compose_subtask_text` 拼「intent+上游摘要」（截断 2000 字、上游 hit_cap 如实标注未完成） |
| 层内串行（同层无依赖子任务排队烧时间） | p4.3b：`ThreadPoolExecutor` 层内并行（`DAG_MAX_CONCURRENCY` 默认 3，1=串行回落）；`EventSequence` 加锁保并发 seq 不重复；结果按子任务序重建保确定性 |
| multi 路由 `tokens_used` 不汇总 → settle `actual=0` 全额退回（账目破洞） | p4.3c：`AgentResult.tokens_used` + `multi_node` 汇总各子任务 `brain.usage`；真跑 3 子任务 15577 tokens 如实入账 |

## 关键工程决策

1. **并行用线程池而非裸 asyncio.gather**：ReAct（LlmBrain.next_step）是同步函数，gather 包同步函数不会并行；run_task 本身跑在 worker 线程，线程池是正确姿势。
2. **multi 子任务脑改非流式（stream=False）**：并行时若各子任务逐字推 content_delta，多 Agent 终答字符级交错成乱码；块状推送下每个子任务的思考/终答是完整事件。单 Agent 路径逐字流不变。
3. **并行度默认 3 + 配置化 + 1=串行回落**：防 LLM 渠道限流；出问题可一键关并行回基线。
4. **结果顺序确定**：并行完成顺序不固定，`run_dag` 按 `dag.subtasks` 重建返回，汇总文本可对账。

## 冒烟抓到的真 bug（本迭代最大意外收获）

**非流式 brain 漏了 p6.3 混合策略**：协议 B 说"任务已完成→直接写自然语言终答"，流式路径有 `looks_like_json` 判定认这条，非流式路径只认 JSON——自然语言终答被当「无法解析」直接停掉。p4.3b 把 multi 子任务切成非流式后，**所有并行子任务全部哑火**，真跑冒烟立即暴露。修复：以 `{` 开头但非法 → 如实停止；非 JSON → 自然语言终答。两条路径判定一致。
