# 迭代总结 · v1.0.0-p5.2 — 文档读取工具 + Demo 页 Agent 身份展示 + db_query 实库验证

> 承接 p5.1a/p5.1b。Tag：`v1.0.0-p5.2`。

## 1. 目标
① 工具池补**文档读取**（read_document，路径护栏 + pypdf）；② **Demo 页展示"当前回答 Agent"**
（后端身份事件 + 前端徽章）；③ **db_query 接真实 MySQL 验证**（实库，非 SQLite）。

## 2. 做了什么
- `orchestration/tools_doc.py`：`read_document`——**路径穿越护栏**（resolve 后必须在
  documents_dir 内，`..`/绝对路径/软链逃逸全拒）、格式白名单（.md/.txt 直读、.pdf 用
  pypdf 懒导入）、max_chars 截断并如实标 truncated、空文件/不存在/不支持格式一律如实报错。
- `config/agents.yaml`：general、report_generation 工具白名单加入 read_document。
- `graph.py`：single_node 发 `status(agent, "running")`——**"当前是谁在回答"上流**；
  demo canned 序列补一条 `rag_retrieval` status（演示页立刻可见）。
- 前端：`derive.ts` 增 `deriveCurrentAgent`（过滤 planner/orchestrator 编排角色，取最近业务
  Agent）+ `agentLabel` 中文映射；`DemoPage` 顶部徽章"当前回答：XX Agent"。
- `compose`：backend 挂 `./backend/data:/app/data:ro`（容器内文档只读）；pytest.ini 固化
  `--basetemp=.pytest_tmp`（受限环境系统 tmp 重复 mkdir 会被误拒）并 gitignore。

## 3. 否掉的方案（最值钱）
- **徽章数据源不做专用新事件类型**：复用 status 事件（协议不膨胀），前端派生函数对
  demo canned 流与真 /tasks 流同一套逻辑。
- **pdf 解析不引 MinerU**：pypdf 已在 requirements（p0 锁定），轻依赖先满足"读文本"；
  版面/公式级解析是 RAG 域的活，不越界。
- **单测 tmp 目录固定项目内**：绕开沙箱对系统 tmp 的误拒，且不污染全局。

## 4. 验证
- `pytest backend/tests`：**113 passed / 3 skipped**（+10：doc 工具护栏/白名单/截断/穿越拒绝）。
- 前端：`tsc -b` ✅、`vitest` **21 passed**（+4：deriveCurrentAgent/agentLabel）、`vite build` ✅（gzip 51KB）。
- **真 LLM 端到端**：任务"读 handbook-demo.md 并总结差旅报销要点"→ general Agent →
  Brain 决策调 `read_document{'file_name':…}` → 读到 164 字 → 总结要点；
  事件流含 `[status] general running`（徽章数据源真流验证）。
- **db_query 实库**（backend 容器内真调 MySQL office 库）：
  - `SELECT * FROM user` → 真实列结构与种子行（dev/superadmin）；
  - `SELECT ... FROM wallet` → 真连库 + 自动 LIMIT 生效（空表如实 0 行）；
  - 查不存在的列 → 数据库错误**如实上抛**（不吞不编）；`SHOW/DROP` → 护栏拒绝。
- **容器内 read_document**：读挂载卷文档 164 字 ✅。

## 5. 风险 / 已知遗留
- read_document 仅限 backend/data/upload（演示文档不入库，backend/data/ 已 gitignore）；
  用户真实上传文档的入口（前端上传→该目录）是下一块。
- 前端徽章的中文名映射是静态表，与 agents.yaml 的 name 需人工同步（低频变更，可接受；
  后续可由 /models 类接口下发）。
