# v1.0.0-p4.3a — DAG 上游结果传递给下游子任务

**类型**：Phase 4 补齐（p4.3 第一刀）｜ **日期**：2026-10-23
**计划依据**：`docs/PLAN-p4.3-DAG结果传递与层内并行.md` 任务 1+2；设计文档 §四.3「支持串行/并行后汇总」

## 背景

p4.1 落地 DAG 拓扑分层调度时明确留了遗留项：`orchestrator.py` 注释「基线层内串行…并行化留作后续」。实读代码发现比"并行"更根本的缺口——**依赖边只决定执行顺序，上游产出对下游不可见**：`graph.py` 子任务文本只有 `f"{st.intent} 任务"`，"先清洗再分析"里的分析 Agent 拿不到清洗结果。

## 交付内容

- **`orchestration/orchestrator.py`**：
  - 新增纯函数 `compose_subtask_text(intent, upstream)`：intent + 上游 final 摘要；单上游截断 2000 字并标注；上游 `hit_cap` 时标注「未完成…不要当作已完成的数据」（§四.5 失败不伪装）。
  - `run_dag` 的 `agent_runner` 签名扩展为 `(Subtask, dict[str, AgentResult])`，upstream 只含**直接**依赖（按 depends_on 过滤）；无依赖传空 dict，与 p4.1 行为一致。
  - `default_agent_runner` 同步接住 upstream 并拼装文本。
- **`orchestration/graph.py`**：`spec_agent_runner._run(st, upstream)` 改用 `compose_subtask_text`，下游子任务真正接上一步的产出。
- **测试**（`tests/test_orchestrator.py` +6 用例）：上游透传（含只传直接依赖）、无上游向后兼容、文本含上游 final、上游失败如实标注、长上游截断。
