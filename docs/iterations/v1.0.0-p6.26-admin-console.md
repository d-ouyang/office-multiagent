# v1.0.0-p6.26 — 管理端升级为独立页面（4 板块）

**类型**：功能（体验补齐）｜ **日期**：2026-10-23
**背景**：p6.25 的管理端只有侧栏一个按钮 + 单板块、无独立 URL，用户问"是不是没有专门的管理端页面"。属实：能进，但不够"专门"。本刀升级。

## 一、交付内容

### 独立路由
- `/admin`（也认 `#/admin`）直达管理端；前端没有引 react-router，用 20 行极简路由（`readView` 纯函数 + `popstate/hashchange` 同步 + `history.pushState`）。
- nginx 已是 `try_files $uri /index.html`，刷新 `/admin` 不会 404。
- 非管理员直接输入 `/admin` → 静默回工作台（后端仍会 403，前端不做安全边界）。

### 四个板块
| 板块 | 内容 |
| --- | --- |
| 用户与额度 | 列表（工号/用户名/角色/余额）、搜索、行内充值、展开流水（含充值金额） |
| 用量概览 | 6 张指标卡（用户数/余额合计/本月消耗/累计充值/任务总数/暂停中）+ 近 7/14/30 天消耗条形图 |
| 任务监控 | 全局任务表（时间/用户/状态/暂停原因/摘要/tokens），可按状态筛选 |
| 系统状态 | 服务健康（mysql/redis/chroma）+ 对话模型数量 + 已注册模型清单 |

### 后端新增（均 `_require_admin`）
- `GET /api/v1/admin/overview`：用户/余额/任务总数/今日任务/暂停数/**本月消耗（只计 kind=task 的 settle）**/**累计充值（只计有 amount 的充值行）**。
- `GET /api/v1/admin/usage?days=7~30`：按天分桶的消耗与次数（`DATE(created_at)` 分组）。
- `GET /api/v1/admin/tasks?status=&limit=`：全局任务（join session→user 取用户名）。
- 迁移 `0009_ledger_amount`：`token_ledger.amount`——**p6.25 的充值行只记了 note、没记金额**，概览要算"累计充值"必须有金额；存量行 amount 为 NULL，如实不计入（不臆造历史金额）。
- `TokenPool.credit` 落 amount；`recent()` 返回 amount。

## 三、已知限制

- 概览与用量是实时聚合查询（数据量大了要加索引/物化视图；当前 40 条任务无压力）。
- 任务监控只读（不能在页面上代用户续跑），避免管理员越权操作他人任务。
- 存量充值金额（p6.25 之前）不可回填——note 里只有操作人，没有金额。
