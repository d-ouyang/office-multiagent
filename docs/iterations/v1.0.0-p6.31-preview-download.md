# v1.0.0-p6.31 — 预览升级：去技术文案 + 下载 + 大文件分页预览（2026-10-24）

> 用户反馈三件事：① 预览头部"服务器上的文件"这类技术文案不友好；② 预览没有下载；③
> 236 行的 xlsx 只显示 20 行。本版全修。

---

## 一、文案去技术化

| 位置 | 旧 | 新 |
|---|---|---|
| 预览浮层头部 | 「服务器上的文件」 | 类型徽章（表格 / PDF / 文档 / 图片 / 文件） |
| 附件 chip title | 「查看服务器上的这份文件」 | 「查看这份文件」 |
| 输入条文件入口 | 「查看已上传到服务器的文件」 | 「查看我的文件」 |

原则（用户拍板）：界面文案不出现服务器/客户端/前端/后端/代理/部署等技术名词。

## 二、下载

`/documents/content?name=…&download=true`：返回**原始文件**（`content-disposition: attachment`）。
此前 csv/xlsx 的"预览响应"是抽取文本（20 行截断版）——没有真下载。前端 FilePreview 头部
新增「下载」按钮（blob + a[download]，带登录态）。

## 三、大文件表格预览（分页 + 滚动增量加载）

**真相澄清**：236 行文件本身是完整的（落盘即全量），20 行是 `TABLE_PREVIEW_ROWS=20`
的抽取上限——那是给 Agent 读表用的上下文截断，预览接口复用它把截断漏给了用户。

方案（无第三方库、无 worker，够用且稳）：
- **后端** `GET /documents/table?name=&offset=&limit=&sheet=`：csv/xlsx 专用分页端点，
  返回 `{columns, rows, total, offset, limit, sheets, sheet}`；limit≤200；xlsx 多工作表
  可切换（sheets 清单 + sheet 参数）；路径校验与预览同闸（本人目录 + `_generated_file` 白名单）。
- **前端** FilePreview 表格分支：首次取 50 行 → **IntersectionObserver 滚动到底自动取下一页**
  （append，不重置）；头部常驻「共 N 行，已显示 M 行」；表头吸顶；多工作表 tab。
  不做一次性全量渲染，236 行与 1 万行体验一致。
- pdf 预览本就是浏览器原生分页渲染（iframe），维持现状。

## 测试与真机

- pytest **342 passed / 3 skipped**（新增 test_p631_preview 7 例：分页/工作表/越权 400/
  非表格 400/下载原始字节）；vitest **80 passed**；tsc 干净。
- 真机（对昨天生成的 236 行 e-f8a39332b0641ee8.xlsx）：
  - `/documents/table` → total=236、每页 50；
  - `download=true` → 11.7KB 原始 xlsx（`file` 识别 Excel 2007+）；
  - Playwright 点"生成文件"卡片 → 预览浮层（徽章「表格」+ 下载按钮）→ 连续滚动 →
    底部显示「已全部加载 · 共 236 行，已显示 236 行」。
