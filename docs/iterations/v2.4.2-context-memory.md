## 一句话

用户回一个「需要」，模型反问"需要什么"——根因是一行 `answer[:80]`。本版把"会话记忆"从切片改成真正的摘要，并把账本对清楚。

## 一、事故与诊断

### 现象

会话 `s-e499d391c1c73389`：第一轮答完后问「需要我把这份热力图+分析导出成文档吗」，
用户回「需要」，第二轮被判成 general/闲聊，`ask_user` 反问"需要什么帮助"。

### 复现（生产库真数据）

"需要"那一轮，模型实际收到的文本：

```
【近期对话】最近几轮原文要点。
用户：统计最近两个月各城市、各月份的销售额，画一张城市×月份的热力图
助手：已按你的需求拉数并画好热力图。下面先说口径，再给结论。 **数据口径** - 数据源：锅圈订单库…- 时
用户：需要
助手：任务已暂停，等待补充输入。
【本轮问题】
需要
```

三个致命点：

1. `history_round_chars=80`，`compress_rounds` 是 `question[:80]` / `answer[:80]` **纯切片**——730 字的回答被砍到 80 字，砍完正好停在「- 时…」，**结尾的提问根本没进去**；
2. 块名叫【历史摘要】，实际用的是**同一个切片函数**——不存在任何摘要；
3. 指代提示只在当前句含「这个/那个/它」时注入，「需要」两字不含代词 → 无任何对齐线索。

## 二、做了什么

### P0 上下文正确性（核心）

| 改动 | 内容 |
| ---- | ---- |
| 近 8 轮原文 | `history_recent_rounds` 4 → 8；近期轮次**原文直出**，不再截断 |
| 结构化摘要 | 新增 `summary.py`：规则抽取（结论/数字/产物/**未决问题**）+ 可选 LLM 归纳 + 合并 |
| 合并策略 | **叙述层用模型**（意图、结论），**事实层用规则**（数字、产物、问句）——模型改写数字是摘要最危险的失真 |
| 摘要落库 | 新表 `session_summary`（迁移 0015），一轮一条，**生成后永久复用** |
| 指代对齐 | 不看用户说了什么，看**上一轮有没有悬着的提问**——「需要/继续/你看着办/按你推荐的来」全覆盖 |
| 降级链 | 超预算从最老整轮丢（丢的即时生成摘要）；**最近 2 轮 + 本轮问题硬保留** |
| 语义变更 | `history_round_chars` 从"每轮切多少字"改为"单条摘要字符上限"（1500） |

### P1 预算与输出

| 改动 | 内容 |
| ---- | ---- |
| 输出预留自适应 | `_desired_output()`：预算充足给满 8192，紧张时降到一半。**没做"按步骤分档"**——ReAct 每次调用无法预知是 JSON 决策还是长终答，按 1024 会把长答案腰斩 |
| 历史预算 | `history_budget_window_pct` 60 → 75 |
| 观察截断 | 不只说"已截断"，补"可用 offset 续读 / headings 定位章节" |
| 表格预览 | 20 → 50 行 + **每列统计**（min/max/均值/不同值数）；`clean_table` 预览 5 → 20 |

### P2 账本对账

`token_ledger` 本来就有 `input_tokens / output_tokens / cache_read` 三列，**但结算时从来没写入**——
只有 `reserve`（预扣）和 `settle`（折扣后额度），真实用量散落在 `done` 事件里，两边对不上。

改：`settle()` 补三列写入 + `graph` 两处传真实 `prompt/completion` 拆分。

真跑样例：

```
reserve=2000  settle=6697  输入=12552  输出=385  缓存=8320
```

账本自洽：`billed = (12552+385) − 8320 + ceil(8320×0.25) = 6697` ✔

**同时暴露一个新问题**：预扣 2000，实际扣 6697——`token_estimate_default` 的预估偏低约 6 倍。

## 四、四个教训

1. **默认值是最隐蔽的契约** —— `[:80]` 藏在一个 try/except 里，比显式的 50 更狠；限制类逻辑必须测"不传参"路径。
2. **块名会骗人** —— 【历史摘要】这个名字让人以为有摘要，实际是切片。命名要和行为一致，否则排障时会被误导。
3. **模型改写数字是摘要的头号风险** —— 摘要是下一轮唯一的事实来源，写错一个数字，后面全错且无人察觉。所以事实层永远用规则抽取。
4. **写库顺序会被真跑教做人** —— 摘要生成最初放在 `append_message` 之前，`turn_no` 取到 0 直接跳过；手动调用却成功，只有真跑才暴露。
