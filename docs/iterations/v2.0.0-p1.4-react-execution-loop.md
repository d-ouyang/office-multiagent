# v2.0.0-p1.4 · react 执行环：多 call 串行执行与事件映射

## 1. 目标

`run_react` 消费 `Step.calls`：一轮多个 tool_calls 串行执行，每个 call 独立发 `tool_call_start/end` + `observation`，历史按"每个 call 一条 Step"回填供 brain 重建 tool 消息。

## 2. 交付

- `Step` 扩展：`calls`（本轮全部调用）、`call_id`（单 call 原生 id）、`parse_error`。
- 执行环重构为「动作单元」：tool_calls 多 call → 展开为 N 个单元串行执行；json 路径单元即原 Step，**行为逐字节不变**。
- 事件映射：`tool_id` = 原生 call id（json 路径仍为工具名，前端零改动）；每单元 start → 执行 → observation → end，成功/失败、耗时、artifact、visual、外部 token 逻辑原样复用。
- `parse_error` 单元：**不真执行**，直接回"工具参数解析失败"观察 + 失败 end 事件（红线：不抛崩整图）。
- 未知工具：走 `tools.call` 的 `CAPABILITY_MISSING` 观察通道，任务不崩可收敛（真跑路径与 json 模式同源）。
- 护栏沿用：重复调用去重、invalid 连击收尾、max_iterations、cancel——按单元粒度生效；逐步用量 label 对多 call 显示"调用 N 个工具"。

## 3. 方案取舍与否掉项

- **先串行执行**（改造文档建议）：一轮多 call 与 DAG 线程池并行是两层事；并行收益等灰度数据说话。
- 历史 N 步而非一条 assistant 带 N calls 的消息：brain 重建逻辑简单、与"一步一调用"的既有 dedup/摘要机制天然兼容；协议上逐条 assistant+tool 亦合法。
- 不改 `events.py`：`tool_call_id` 复用现有 `tool_id` 字段，前端零改动。
