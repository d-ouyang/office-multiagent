# 迭代总结 · v1.0.0-p3.1 — Planner + Router（意图识别 / 复杂度打分 / 路由）

> 对应计划：PLAN-1.0.0.md Phase 3 / v1.0.0-p3.1。Tag：`v1.0.0-p3.1`。DAG 拆分留到 p3.2。

## 1. 目标
落地设计文档 §四.2/§四.3 的前半：**任务规划器 Planner**（意图识别 + 复杂度打分）与**路由器 Router**（简单→单 Agent / 复杂→多 Agent），并用 LangGraph 把「路由真正驱动控制流」跑通、推 NDJSON 事件。

## 2. 做了什么
- `config/planner.yaml`：意图关键词表（analysis/cleaning/report/rag/visualization/image_restore → 对应 Agent 类型）+ 复杂度打分的连接词/权重/阈值。**配置驱动，非硬编码**。
- `core/planner.py`：`plan(text) -> Plan{intents, intent_hits, score, signals, entities}`。意图按关键词命中强度排序；复杂度分 = 步骤连接词 + 多意图 + 多输出 + 文本长度 + 依赖词，`signals` 保留打分明细（可解释、可对账）。
- `core/router.py`：`decide(plan) -> RouteDecision{mode, reason, score, threshold, primary_agent}`，按 `complex_threshold` 分流。
- `orchestration/graph.py`：LangGraph `StateGraph`——`planner` 节点 → 条件边按 `route` → `single`/`multi` 桩节点 → END。**共享 `RunEventEmitter`** 保证跨节点 `seq` 单调；节点推 `status`/`thinking_delta`/`content_delta`，收尾 `done`。
- `api/routes.py`：`POST /api/v1/plan`（返回路由决策 JSON）+ `POST /api/v1/tasks`（跑编排、NDJSON 流式返回事件）。均受网关 JWT 保护。
- `core/config.py` 加 `planner_config`。

## 3. 否掉的方案（最值钱）
- **复杂度/意图不用 LLM 实时判，用确定性规则打底**：这类判断高频、低延迟、要可测（§十二"算数交给代码、LLM 只做推理"；§12.5 JEV 决策层接口化）。规则版零成本、无网络抖动、可精确断言；LLM 增强（DAG 分解、歧义消解）留作 `DecisionModel` 插槽，改配置即接。
- **不在各节点各建 emitter**：那会让 `seq` 每个节点重头（前端按 seq 排序会乱）→ 用共享 `RunEventEmitter`，跨节点单调。
- **p3.1 不搭真实 ReAct/Orchestrator**：节点先返回桩结果 + 推事件，把「路由驱动 LangGraph 控制流 + NDJSON 协议」这条主干跑通；真实 Agent 循环在 Phase 4。
- **事件收集后流式**（`/tasks`）：确定性骨架够快；真正的逐节点异步流式（async 节点 + 队列）留待 Phase 4 接入长任务时再做。

## 4. 验证

## 5. 风险 / 已知遗留
- 规则版意图/复杂度对歧义、口语、长上下文可能误判——用 `signals` 可解释 + LLM 插槽缓解（后续）。
- `/tasks` 为收集后流式 + 桩 Agent；真实执行在 Phase 4。
- 实体抽取（数据源/时间/维度）仅做了输出格式，§四.2 的完整实体抽取随 DAG（p3.2）补强。
