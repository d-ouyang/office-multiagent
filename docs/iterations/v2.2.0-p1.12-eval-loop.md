## 三件套

### E1 golden set（backend/evals/golden_set.jsonl，10 条）

断言维度是【编排行为】而非 LLM 文采：route（planner 纯规则，确定性）、
tools_called（tool_call_start 事件集合）、任务级无 error。覆盖：
- 订单三形态（统计/城市筛选/**p5.5 劫持回归**"查一下最近10笔订单"）；
- 对比/报表/导出/知识库检索各一；
- **multi 路由**（rag+analysis 组合——analysis 覆盖面大，用 rag 才能构造出 multi，
  校准自实测：planner 规则对"先清洗然后报表最后画图"判 single）；
- 无工具用例（general）。

### E2 双入口评测

- **pytest**（tests/test_golden_set.py，CI 门禁）：sqlite 自建表环境，工具真执行
  （订单表缺失 → 工具失败属预期——不断言工具结果）；
- **CLI**（backend/scripts/run_evals.py）：真实环境库校准/抽样用
  （`--filter/--case`；本地 mysql 不发布端口，容器内跑或发布临时端口——与 pytest
  断言集完全同源）。

### E3 CI 门禁（deploy workflow 新步骤）

构建镜像**之前**：runner 宿主持久 venv（/opt/office-test-venv，首次装后缓存）跑
`pytest -q tests/`——**全量单测 + golden set 不过不部署**。

## 实现中校准/踩过的坑（记录防复发）

1. **decision-llm 消耗脚本**：planner 的意图决策增强（intent_decision）在 brain
   之前调 LLM——FakeModelAdapter 的弹出语义脚本会被它吃掉首项。换 **EvalAdapter**
   （常驻适配器，按 model_id 分支：decision 请求返回不可解析 JSON → 决策回落规则
   →路由确定性；brain 请求按序返回 action/final）。
2. **multi 用例校准**：analysis 的 single_agent_covers 覆盖面大（5 意图），
   "清洗→报表→画图"实际判 single——multi 用 rag+analysis 组合构造。
3. **conftest 铁律冲突**：autouse `_no_real_llm` 清空 key → brain 回落 StubBrain
   （不调工具，评测失效）——评测用例按 conftest 约定**显式补 dummy key**（EvalAdapter
   不真联网，不违反铁律精神）。

## 门禁语义

改 planner.yaml 关键词/路由阈值/agents.yaml 工具清单/system_prompt → golden set
红 → 阻止部署。golden set 的扩充原则：**线上每修一个路由/工具选择类 bug，就进一
条回归用例**（gs-007 即 p5.5 劫持的回归）。
