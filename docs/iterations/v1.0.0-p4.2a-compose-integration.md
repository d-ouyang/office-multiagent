# 迭代总结 · v1.0.0-p4.2a — 三层联调 + Compose 就绪修复（任务：全栈联调）

> 对应计划：Phase 4 整合验证。Tag：`v1.0.0-p4.2a`。应用代码未改（仅 Dockerfile / compose），单测仍 65 passed。

## 1. 目标
把 Phase 4 的各层真正连起来验证（三层联调：前端→网关→backend→DB→NDJSON→渲染），并让 `docker compose up --build` 就绪。

## 2. 做了什么 + 联调发现
- **修真 bug（关键）**：`backend/Dockerfile` 只 `COPY app/ tests/`，**漏了 `config/`**——`models.yaml`/`planner.yaml`（p3.x 新增）不进镜像，容器里 `/models`、`/plan`、`/tasks` 会因找不到配置而 500。已补 `COPY config/ ./config/`。
- `docker-compose.yml`：infra pin 到 `mysql:8.0` / `chromadb/chroma:0.5.23`（与 RAG 同机缓存一致，也落实"生产 pin 版本"）；`gateway`/`frontend` Dockerfile 基线用已缓存 tag（`node:20-alpine`、`nginx:alpine`），backend 保持 `python:3.13-slim`（numpy 2.5/pandas 3 需 ≥3.12）。
- **三层联调（宿主进程，真 HTTP）**：起真 backend（uvicorn）+ 真 gateway（`nest build` 产物 `node dist/main`，指向真 backend）：
  - 网关 `/api/health` ok；
  - 公开 `/api/v1/demo/stream` 经网关透传到**真 backend**，NDJSON 逐行流出；
  - 受保护 `/api/v1/tasks` 无 token → **401**；
  - 带有效 HS256 JWT → 真编排 NDJSON（planner→DAG 拆 3 子任务→status）。**闭合了 p2.1a 只用假后端没验到的"网关↔真后端"链路**。
- 前端层：`vite build`（gzip 51KB）+ 17 单测 + `nginx.conf` 反代 `/api`→gateway（p2.1b 已覆盖）。

## 3. 否掉的方案 / 阻塞（最值钱）
- **沙箱内 `docker compose up --build` 五容器未能跑通**：Docker  registry 出网被限——`python:3.13-slim` 基线三次拉取（docker.io / USTC / NetEast）均**零进度**卡死（pip 的腾讯源、npm 的 npmmirror 都通，唯独 Docker 守护进程拉镜像挂）。故基线段改走"本地已缓存 tag"绕过，backend 仍需 `python:3.13-slim`（未缓存、拉不动）。
- 处置：改为**宿主进程三层真联调**（不依赖镜像），验证网关↔真后端；完整 `docker compose up --build` 交**本机**（Docker Hub 可达）执行——配置已就绪。

## 4. 验证
- 应用单测：`pytest backend/tests` **65 passed / 3 skipped**（本轮未改应用代码，仍全绿）。
- 三层真联调：网关→真后端公开 NDJSON 透传 ✅；受保护 401 ✅；有效 JWT→真编排 NDJSON ✅（见 §2）。
- 修复的 Dockerfile 缺口：容器 backend 现含 `config/`（`COPY config/`）。

## 5. 风险 / 已知遗留
- **`docker compose up --build` 五容器未在沙箱实跑**（registry 出网受限）——需在 Hub 可达的环境（本机）跑；compose/Dockerfile 已就绪。
- 未接真实 mysql/chroma 的联调（宿主联调时 DB 降级）；真实 LLM / 办公能力未接（Phase 5）。
