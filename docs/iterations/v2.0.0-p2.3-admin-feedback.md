# v2.0.0-p2.3 · 管理端「意见反馈」页

## 1. 目标

管理员查看反馈闭环数据：统计卡（总量/赞/踩/点踩率/Top 原因）+ 筛选明细分页；只读，不提供删除/修改。

## 2. 交付

- **接口 `GET /api/v1/admin/feedback`**（`_require_admin` 双闸内）：
  - 筛选：rating / tag（tags JSON 文本 LIKE，MySQL+SQLite 双兼容）/ 关键词（comment 或回答内容）/ 分页；
  - **统计口径不含 rating 筛选**——切赞/踩列表时总量与点踩率稳定可比；Top 5 原因取最近 500 条聚合；
  - 明细带 username / employee_id / message_snippet（回答前 80 字）/ session_id（可复制跳任务监控排查）。
- **前端**：
  - `admin/nav.ts` 第六个一级入口「意见反馈」（`LikeOutlined`）；
  - `admin/FeedbackTab.tsx`：4 张统计卡 + Top 原因（点击即筛选）+ 评分/原因/关键词筛选 + 表格（时间/用户/工号/评分/原因+说明/回答摘要/会话）+ 分页；沿用 TasksTab 的 AdminListPage/AdminPager/防抖模式；
  - `lib/api.ts` `adminFeedback()`。
- 测试：`test_admin_feedback.py` 3 例（统计+列表、三种筛选、非管理员 403/匿名 401）；admin 导航测试更新为六入口。

## 3. 方案取舍与否掉项

- **只读**：反馈流水是改进依据，管理端删改会破坏"用户说了什么"的完整性（与审计同一纪律）。
- tag 筛选用 LIKE 而非 MySQL JSON_CONTAINS：单测走 SQLite，跨库兼容优先；tags 是受控白名单值，LIKE 精确匹配 `%"tag"%` 无误伤。
- Top 原因基于最近 500 条：反馈量级小（办公场景），全量聚合收益低；量大后可换 SQL JSON_TABLE。
- 统计不含 date 筛选：时间窗统计等真实使用出现需求再加，避免过度设计。
