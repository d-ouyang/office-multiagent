## 1. 目标
落地设计文档 §四.3/§四.4/§四.5：**单 Agent ReAct 循环**（Thought→Action→Observation，max_iterations 防跑飞）、**Orchestrator 按 DAG 拓扑分层调度 + 汇总**、**工具兜底**（重试/能力缺失不胡编）。接进 LangGraph，跑通**后端编排闭环**。

## 2. 做了什么
- `orchestration/tools.py`：`ToolRegistry.call` 带退避重试（≤2）；工具缺失返回 `CAPABILITY_MISSING`（如实告知、不胡编，§四.5）。
- `orchestration/react.py`：`run_react`（ReAct 循环，`max_iterations` 超限强制阶段结论）+ `Brain` 协议 + `StubBrain`（确定性基线，无 LLM、可测；LLM brain 按协议后插）。
- `orchestration/orchestrator.py`：`topo_levels`（DAG 分层，同层可并行）+ `run_dag`（按层执行子任务 + 汇总）。
- `orchestration/graph.py`：single 节点跑 `run_react`，multi 节点 `run_dag`；共享 `RunEventEmitter` 保 seq 单调，推 status/thinking/tool_call/observation/content/done。
- `pytest`：57 passed / 3 skipped（新增 test_tools 4 / test_react 4 / test_orchestrator 3 / /tasks 端点回归 1）。

## 3. 否掉的方案（最值钱）
- **Brain 可插拔 + 确定性 StubBrain 打底**：不接真实 LLM（成本/延迟/不可测），先把循环/调度/兜底机器跑通；LLM brain 按 `Brain` 协议插入（承接 §12.5 接口化）。
- **层内串行基线**：`run_dag` 按拓扑层执行，同层本可并行，但基线串行（确定性、可测）；并行化（asyncio.gather）留后续，接口已按"层"组织好。
- **超限不硬编答案**：ReAct 到 `max_iterations` 只给"已达上限"的阶段结论，不伪造终答（§四.4 + 兜底原则）。
