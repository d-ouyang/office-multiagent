## 端点

`GET /api/v1/runs/{run_id}/replay` —— 四套日志按 run_id 合一（B2 的 trace_id=run_id
是钥匙），一次返回：

```json
{
  "run":         { run_id, session_id, status, text, result, tokens_used,
                   pause_reason, pause_payload, retry_of, request, created_at },
  "events":      [ ...该 run 的全部编排事件（message.trace 按 run_id 过滤） ],
  "tools":       { "invocations": [...], "call_log": [...] },   // C1 幂等表 + 旧日志
  "usage":       [ ...token_ledger 流水（reserve/settle/kind/model） ],
  "dead_letter": [ ...run.dead_letter 审计（C2） ]
}
```

全程只读；排查/回放/评测取样任取一角，不用再跨四张表手工 join。

## 设计拍板

1. **events 从 message.trace 取**（而非新表）：trace 已随消息落库（B2 起逐事件带
   run_id），回放端点只做过滤——零写入路径、零新表。
2. **权限与会话同口径**：本人（session 归属）或 admin；非本人 → 404 不暴露存在性
   （与 session_belongs_to 的 404 语义一致，不走 403 防 run_id 穷举探测）。
3. **工具日志双源**：tool_invocation（C1，有观察）与 tool_call_log（旧表，含 error）
   并列返回——历史 run 只有后者，新 run 两者都有，不强行合并 schema。
4. 新文件 `app/api/runs_api.py`（routes.py 已 3200+ 行），main 挂载 prefix=/api/v1。

## 测试（tests/test_replay.py +4）

- 四套日志聚合正确、events 按 run_id 过滤（他人事件不混入）；
- 非本人 404 / admin 跨会话可看 / 本人可看 / run 不存在 404。
