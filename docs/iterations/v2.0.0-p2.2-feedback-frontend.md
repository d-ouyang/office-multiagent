# v2.0.0-p2.2 · 前端点赞/点踩 + 反馈弹窗

## 1. 目标

消息反馈闭环的用户侧：回复行点赞/点踩图标接真接口（激活态实心），点踩弹窗（抱歉话术 + 8 原因 tag 多选 + 其他原因 0/200），DB 为真相源、刷新/切会话后状态保持。

## 2. 交付

- **`lib/api.ts`**：`FEEDBACK_TAGS`（8 项，与后端白名单一致）+ `submitMessageFeedback()` / `cancelMessageFeedback()`；`getMessages()` 返回值补 `id` / `feedback`。
- **`FeedbackDialog.tsx`**（新组件）：标题「抱歉，这次回答没能帮到你」+ 副文案；tag 多选 chip；选中「其他原因」展开多行输入（maxLength=200 + `n/200` 计数）；**至少 1 tag 或有文字才能提交**（按钮禁用态）；**遮罩点击不关闭**（防误触丢填写），仅 X 关闭；错误信息原样显示（如服务端 400 文案）。
- **`ChatMessage.tsx`**：`vote` 本地假状态替换为 `feedback` 服务端当前态；
  - 状态机（PLAN §4.1）：点赞直接落库；**激活态再点 = 取消**（DELETE）；点踩必走弹窗；提交成功弹窗关闭 + 图标转实心；
  - 激活态实心：`.reply-meta .icon-btn[aria-pressed="true"] svg { fill: currentColor }`；
  - `useEffect` 按消息 `id` 同步服务端态——切会话/刷新后激活态仍在；
  - **无消息 id（流式刚结束的本地消息）不渲染反馈按钮**——反馈须以落库的 message_id 为锚点，刷新后出现。
- **`WorkspacePage.tsx`**：历史消息映射带 `id/feedback`；`onFeedbackSubmit/Cancel` 回调接 API，`UNAUTHORIZED` 统一登出，业务错误抛回弹窗展示。

## 3. 方案取舍与否掉项

- **流式刚结束的消息暂不能反馈**（按钮不显示）：流结束时前端没有 message id（done 事件不带）；重新拉列表/刷新后可反馈。若要闭环更紧需后端 done 事件带 message_id，列入后续优化。
- **取消后再点踩 = 全新反馈**（不回显旧原因）：状态机里"激活点踩→直接取消"优先，覆盖语义由服务端流水承担（append-only，旧信息保留）；弹窗回显是死代码，不引入。
- 遮罩不关闭但 Esc 关闭未做——与"防误触丢填写"一致，后续可加"填写中 Esc 先确认"。
