# v1.0.0-p6.32 — 办公交付能力、混合意图识别与单任务 token 上限（2026-10-24）

## 目标

把 p6.30 真任务暴露出的「订单筛选太死、交付格式少、图表不好看、意图误拆、单任务无成本上限」
一次收口成可独立使用的办公链路。

## 交付

- **订单工具按表字段工作**：城市按门店地址匹配，不限上海/安庆；状态、渠道等不再写死可选值；
  `filters` 支持 eq/ne/contains/gt/gte/lt/lte/in/not_in；导出字段接受中文名或真实列名，PII 仍脱敏或拒绝。
- **流程图**：`render_flow` 只返回节点、边、实走顺序；前端 SVG 自动排版，实走实线+角标，未走分支虚线。
- **图表**：后端继续负责汇总与 svg/png 文件，回答区用官方 ECharts 绘制同一份 `visual` 数据；
  按需动态加载图表模块，普通对话主包不带 ECharts。
- **文件**：`write_document` 新增 PDF/PPTX；容器安装 Noto CJK，PDF 无中文字体时拒绝生成缺字文件。
  （p6.34 修正：Noto CJK 是 CFF 轮廓，reportlab 不能用；已改装文泉驿微米黑，见
  `v1.0.0-p6.34-pdf-truetype-font.md`。）
- **统计方法**：`compare_orders` 用代码算环比、同比、占比，上期为 0 时不伪造百分比。
- **RAG 外部工作流**：办公调用同步 `/api/v1/qa/ask` 并传 `persist=false`；RAG 完整执行检索、重排、
  生成和依据校验，但不写自己的会话/额度/轨迹。该开关只允许持有内部证明的调用方。
  `rerank_score`、`vector_similarity`、`chunk_id`、`grounded` 与 `usage` 全部带回；usage 计入办公任务。

## 混合意图识别

1. 有近期对话且本句确实依赖上文时，用决策小模型改写成独立问题；长期记忆不参与。
2. 独立口语、空意图、多意图、2～4 分边界、否定句或刚改写过的句子，才调用 `decision-llm`
   做封闭 JSON 分类；清楚句仍走零调用规则快路。
3. 多 Agent 不再只看「分数 ≥ 3」：主 Agent 已覆盖分析、清洗、报表、图表时保持 single；
   制度口径 → 数据分析等真实交接才拆 multi。
4. 规则和模型不一致时记录 WARNING（原句、两边标签、模式、理由），供后续用真实误判校准。
5. 统一阈值键为 `complexity_threshold`，修复过去 YAML 写一个名字、代码读另一个名字的问题。

## 单任务 token 上限

- 全员统一配置 `TASK_TOKEN_HARD_LIMIT`，默认 **50,000**，`0` 关闭。
- 与余额门分离：余额门在开始前 reserve；任务上限在运行中限制本任务还能不能发起下一次模型调用。
- 多 Agent 共享一个线程安全预算，调用前按 prompt UTF-8 字节上界预留，向供应商下发 `max_tokens`；
  并行子任务不能同时把同一份余额占两遍。
- 命中后在模型调用边界体面停止，保留已有工具结果和文件，不标成余额不足，也不进入充值续跑。
- 外部 RAG 的一次完整工作流由对方执行，只能在返回 usage 后入账；若单次外部调用跨线，本任务随后立即停止，
  不再发起下一步。内部对话模型受调用前上限约束。
