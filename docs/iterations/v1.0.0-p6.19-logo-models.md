# 迭代总结 · v1.0.0-p6.19 — 锅圈图标、思考耗时与硅基模型

> Tag：`v1.0.0-p6.19`。

## 1. 目标
侧栏和浏览器标签换成锅圈 logo。每段深度思考标出自己的耗时。硅基流动模型按当前清单补齐。

## 2. 做了什么
- 图标直接用 RAG 项目里的 `gq_logo.jpg`。侧栏品牌位和浏览器标签都指向它。
- 同一段思考的耗时用这段事件的首尾时间相减，显示成「深度思考 1.5s」。字数仍在右侧。只有一个时间点时不编一个耗时。
- 硅基流动列表底部增加 LongCat-2.0、Hy4-preview、DeepSeek V4-Pro（1M）、Qwen3.8-27B（256K，思考和视觉）。GLM-5.3-Flash 标成思考和视觉。Qwen3.5-9B 改为 256K。硅基渠道的 DeepSeek V3 和 R1 改为 160K。
- DeepSeek-OCR 不进对话下拉。上下文只有 8K，装不下一轮办公对话。它适合在读扫描件时单独调用，把页面转成 Markdown。限时免费只影响这一步的成本，不改变它该放在哪。

## 3. 否掉的方案
- 不把 DeepSeek-OCR 放进模型选择器。用户一旦把它当主模型，历史和工具结果很容易超出 8K。
- 不给 Qwen3.8-27B 和 GLM-5.3-Flash 下发思考力度。它们默认会思考，力度参数的取值还没在接口上核对，乱传会让请求失败。V4-Pro 与现有 V4-Flash 一样，只接受 high 和 max。

## 4. 验证
- 前端消息、过程切段、侧栏测试通过。
- 模型注册表测试确认新模型在对话列表里，向量和重排模型仍不出现。

## 5. 风险
- 标了视觉的模型，对话请求目前仍只发文字。选中它们还看不到图片。
- 上下文数字来自模型页，程序只用来展示，不会按这个长度截断请求。

## 6. 下一步
订单数据准备好之后，再做按时间和地区查询订单。在那之前，扫描件识别可以接 DeepSeek-OCR 这一小步。
