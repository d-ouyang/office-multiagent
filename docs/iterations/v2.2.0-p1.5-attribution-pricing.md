判据：抽查任一 run 的每步 usage 可归因到人；估算与上报偏差可见。
→ **达成**：① 每个 NDJSON 事件信封带 `trace_id`（=run_id，跨服务续跑同 id 可聚合）
与 `tenant_id`（单租户占位 "office"）——判据用例
`test_run_task_events_carry_trace_attribution` 断言全部事件携带；
② 记账核实结论：**provider 回报 usage 已是结算数据源**（p6.45 的 brain.usage →
steps_usage → settle 链，无 len/4 估算残留）——本步补上缺失的 cache 折扣计价。

## 设计拍板

1. **trace_id 复用 run_id**：跨服务续跑（pause/resume）本就共用 run_id，聚合语义天然成立；不另造 id。
2. **tenant_id 硬编码 "office"**：单租户现实，占位字段（Event 契约 8/8 齐全）；B3 多租户时改入口注入。
3. **折扣默认启用（ratio=0.25）**：这是计价准确性修正（缓存命中成本确实只有 ~1/4），方向是用户少扣钱；要恢复旧行为设 `LLM_CACHE_PRICE_RATIO=1.0`。
4. **网关侧计费归因裁剪到 B3**：预算硬约束需要 user 级归因时，gateway 代理路由再加 X-User-Id 透传（backend 调用头），本步先做 backend 侧闭环。

## 部署注意

- `LLM_CACHE_PRICE_RATIO` 未配置 = 缺省 0.25（折扣生效）；恢复全价设 1.0。
- 部署后验证：发任务抓 NDJSON 行 `trace_id` 非空；`token_ledger` 的 settle 列为 billed 口径。
