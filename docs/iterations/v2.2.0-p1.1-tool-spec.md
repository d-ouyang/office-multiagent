## 元数据拍板（13 工具）

- **只读类**（query_orders/compare_orders/sales_report/db_query/analyze_table/read_document/rag_retrieve）：side_effect=False、idempotent=True、`db:read`/`fs:read`/`rag:query`
- **写文件类**（clean_table/export_orders/render_chart/render_flow）：side_effect=True、idempotent=True（同名覆盖语义）、`fs:write`
- **write_document**：idempotent=**False**（LLM 生成内容，重试=重烧钱+内容漂移）——Phase C1 幂等键的头号靶子
- **ask_user**：side_effect=True（挂起状态落库）、idempotent=True（二次挂起语义）、`hitl:ask`

## 设计决策（不确定时拍板）

1. **ToolSpec 落在 `orchestration/tools.py` 而非计划文档写的 `skills/base.py`**：skills 层运行时零引用（P2 未启用），真实注册表是 tools.ToolRegistry——契约落在活代码上，skills 启用时对齐。
2. **集中批注表**而非逐个 register 加参数：`_TOOL_SPECS` 一处声明全部 13 工具，可审计、改动集中；漏标注由 `unannotated()` + 测试抓红，运行期兜底悲观档（side_effect=True/idempotent=False）。
3. **唯一行为增量**：非幂等副作用工具重试时 WARNING——不拦截（现状红线「非幂等工具副作用风险与现状一致」不破坏），幂等键去重 Phase C1 落。

## 踩坑

- 告警分支最初写在 `if attempt <= max_retries and backoff:` 里——**backoff=0（关退避）时告警也被短路**。告警语义不能依赖退避时长，已拆开。
