# v2.0.0-p1.2 · llm.py 协议面（tools / tool_calls / 流式增量）

## 1. 目标

`llm.py` 具备 OpenAI 兼容工具调用能力：请求可带 `tools/tool_choice`，响应（非流式+流式）能还原结构化 `tool_calls`。本步只做协议面，不改 brain/react 运行路径。

## 2. 交付

- 新增 `ToolCall` 归一化结构：`id / name / arguments(dict) / arguments_raw / parse_error`。
- `chat()` / `_chat_once()`：`tools` 非空才下发，缺省 `tool_choice="auto"`；解析 `message.tool_calls`。
- `chat_stream()`：tool_calls 按 `index` 增量累积（id/name/arguments 分片拼接），**流结束后**统一产出并回调 `on_tool_call`——正文/思考流与工具增量分通道，不交错。
- 错误口径（对齐红线）：缺 id/name = 协议畸形，抛 `LlmError`；arguments 解析失败**不抛**，落 `parse_error` 由上层回填为工具错误；`arguments` 非 object 同样记 `parse_error`。
- 测试 7 个新用例：请求体下发/缺省、解析、坏 arguments、缺 id、流式分片累积、index 乱序还原、不带 tools 时请求体干净。

## 3. 方案取舍与否掉项

- **坏 arguments 不 raise**：按《改造文档》红线「parse 失败回 ToolResult.error，勿抛崩整图」；协议层只标 `parse_error`，处置权留给 react 层。
- **流式工具不逐片回调**：分片对调用方无意义且易交错污染；流结束一次性给完整 ToolCall，p1.4 的事件映射从这里取。
- **Schema 校验不在 llm 层**：llm 不知道注册表；参数按 Schema 的校验放 p1.3 brain / p1.4 react。
- 不改重试语义：解析类失败不属于瞬时错误，不重试。

## 4. 测试

- 定向：test_llm 21 passed（原 14 + 新 7）。
- 全量回归：pytest 411 passed / 3 skipped（含 p1.0/p1.1 新增用例）。
- 真点测（p1.0 探针）：10/10 模型流式与非流式 tool_calls 均可用，与本协议面的解析路径一致。

## 5. 验收与回滚

- 不带 tools 的调用请求体与响应行为与改造前完全一致（存量 14 个 llm 用例未改断言）。
- 回滚 = revert 本提交；`ToolCall` 为新增类型，无其他模块引用。
