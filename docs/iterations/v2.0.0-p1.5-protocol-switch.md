# v2.0.0-p1.5 · react_protocol 开关与灰度

## 1. 目标

协议切换可配置、可回退、fail-closed：`react_protocol: json | tool_calls | auto`。

## 2. 交付

- `settings.react_protocol`（env `REACT_PROTOCOL`），**缺省 `json`**——上线行为与 1.x 完全一致。
- `resolve_react_protocol(mode, model_id, tools)` 判定矩阵：

| 配置 | 模型 supports_tools | 工具 Schema 齐全 | 结果 |
| --- | --- | --- | --- |
| json | 任意 | 任意 | json |
| tool_calls | true | true | tool_calls |
| tool_calls | false/None | 任意 | **json + warning**（禁止硬开） |
| tool_calls | 任意 | false/无工具 | **json + warning**（缺 Schema 硬开=静默退化） |
| auto | true | true | tool_calls |
| auto | 其余 | — | json |
| 非法值 | — | — | json + warning |

- 灰度顺序（与改造文档一致）：单 Agent 内部 → 选模 → 全量单 Agent → multi 子 Agent 第二批。multi 子任务脑当前 `stream=False`，协议面已就绪，按同开关切换。

## 3. 方案取舍与否掉项

- **不做每请求/每会话协议覆盖**：灰度口径要稳定可对比，全局开关 + 分批放量足够；细粒度路由等灰度数据后再议。
- 不支持模型的判定以 `models.yaml.supports_tools`（p1.0 真点测登记）为准，不猜厂商能力。
- 灰度指标（任务成功率、平均步数、无效工具率、坏参数率、延迟、回退 json 比例）依赖日志，本步先以 warning 落地"回退事件"，指标面板归 p2 后管理端统一补。

## 4. 测试

- 协议解析矩阵 6 分支断言（test_brain.py::test_resolve_react_protocol_matrix）。
- 显式 tool_calls 缺 Schema 回落用例（防"看起来接了、线上静默退化"）。
- 全量回归：pytest 423 passed / 3 skipped（p1.3/p1.4/p1.6 新用例一并计入）。

## 5. 验收与回滚

- 缺省 json：不改任何配置部署本版本，线上行为不变。
- 切 tool_calls：`REACT_PROTOCOL=tool_calls`（或 models.overrides 控模型能力）+ `docker compose restart backend`；回退改回 json 即止血。
