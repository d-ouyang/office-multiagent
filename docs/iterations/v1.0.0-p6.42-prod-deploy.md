# v1.0.0-p6.42 — 生产部署上线 office.nianan.site

部署形态：**共享 RAG 中间件**（设计文档 §12.3 预留方案）。服务器 42.192.111.82（腾讯云 4C4G 上海）。

## 为什么不是全量 6 容器

服务器内存 3.6G、可用 2.0G、**swap 已用 1.8/1.9G（在换页）**，还要跑 RAG 七容器 + 1024 两容器。全量栈（自带 mysql/redis/chroma）估算要 1.2-1.7G，大概率 OOM。改为共享：

- 只起 `backend / gateway / frontend` 三个容器（实测内存几乎无增量，可用仍 2.0G）。
- `rag-mysql`（mysql:8.0）/ `rag-redis`（redis:7-alpine）/ `rag-chroma`（chroma 0.5.23）与 office compose 要求**版本完全一致**，直接复用。
- 数据隔离：rag-mysql 新建独立 `office` 库 + 专用 `office` 用户；redis 用 db 2；chroma 共享实例。

## docker-compose.prod.yml（新增）

- 与开发用 `docker-compose.yml` 分离，两份不混用。
- 通过外部网络 `rag-qa-system_default` **按容器名**访问 RAG 中间件——RAG 各端口只绑 127.0.0.1，`host.docker.internal` 在 Linux 上走不通，必须入网。
- 宿主端口只绑 127.0.0.1，由宿主 Caddy 统一反代：前端 **8090**（8080 已被 rag-frontend 占用）、网关 3001 仅宿主调试用。
- 环境变量全放同目录 `.env`（chmod 600）。

## 部署过程踩的坑（都修了）

1. **rsync 带上了本地开发 `.env`** → 服务器端生成被"已存在"跳过，差点拿开发空密钥上线。已把本地 `.env` 挪为 `.env.dev-imported.bak`、强制生成生产配置；**以后 rsync 必须排除 `.env`**。
2. **backend/Dockerfile 卡死在 apt**：`deb.debian.org` 从腾讯云出海极慢，56.7MB 字体包 6 分钟无进展。切 `mirrors.cloud.tencent.com` 后 45s 完成（与 1024 的 apk→阿里云同款教训）。
3. **`alembic upgrade head` 在全新库必炸**：0001 基线把多条 SQL 塞进一个 `op.execute()`，pymysql 不支持多语句（1064）。该路径此前从未真正执行——全新安装一直走 init.sql，老库是 stamp 0001 再 upgrade。**部署改走既定路径：init.sql 灌库 + `alembic stamp head`**；0001 的多语句 bug 留待修复。

## 上线步骤（可复用 runbook）

```
rsync -az --exclude node_modules --exclude ".venv*" --exclude .pytest_tmp \
  --exclude __pycache__ --exclude "*.log" --exclude backend/data \
  --exclude dist --exclude .workbuddy --exclude .env ./ server:/opt/office/
# .env 服务器侧生成（密钥 openssl rand -hex 32；API keys 手工补）
docker exec rag-mysql 建 office 库 + office 用户
docker exec -i rag-mysql mysql -u root -p... office < db/init.sql
docker compose -f docker-compose.prod.yml run --rm backend alembic stamp head
docker compose -f docker-compose.prod.yml up -d --build
# Caddy 追加站点块 → caddy validate → systemctl reload caddy
```

## 冒烟结果（全过）

- 三容器 healthy；`/api/v1/health` → mysql/redis/chroma 全 ok（共享中间件连通）。
- 内存可用部署前后持平 2.0G；磁盘 12G 剩余。
- `https://office.nianan.site/` 200；`/admin` 200。
- 用户登录 `POST /api/v1/auth/login` → 201 + JWT（sub=EMP001, role=admin）；管理端登录 → 200。
- office-backend → rag-backend HTTP 200（RAG 检索链路通）；office-gateway → rag-gateway 可达。

## Caddy 站点块

照抄 qa 站点被验证过的流式模式（NDJSON 友好）：`/api*` → 127.0.0.1:3001（office 网关），其余 → 127.0.0.1:8090（前端 nginx，内部再反代 /api 到网关容器）。备份：`/etc/caddy/Caddyfile.bak-office-20261026`。
