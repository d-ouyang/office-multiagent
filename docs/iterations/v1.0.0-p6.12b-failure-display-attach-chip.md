## 1. 失败归因怎么做的 + quota_paused 无提示 bug（最重要）
**归因链路**：后端 token 池 reserve 失败 → `quota_paused` 事件（reason/balance/needed）+ `done(status=paused_insufficient_quota)` → 前端本应显示。bug 根因：
- 旧实现只有**流式期间的临时 banner**（`events.some(quota_paused)`），done 后 `reset()` 清空事件 → banner 消失，且暂停时 assistant 无 content、气泡空白 → **用户视角=毫无反馈**（病根同 p6.7b「答案消失」：UI 状态没随消息固化）。

**修复**：
- `derive.ts` 新增 `deriveFailure(events)`：`quota_paused`/`error`/`done(paused_*|error)` 归一为 `{kind, title, reason, balance?, needed?, code?}`（done 状态兜底）。
- `ChatMessage` assistant 气泡渲染**专用失败块**：quota=橙色「⏸ 余额不足，任务已暂停：余额 X，本次需要 Y——充值后重新发送即可」；error=红色「⚠ 任务失败：原因 (code)」。**events 已随消息固化，刷新/切会话回来都还在**；流式期间同样实时渲染；失败时不显示「正在思考…」。
- 删掉旧的临时 banner（避免重复）。
- vitest +4（quota/error/兜底/正常完成 null）。
