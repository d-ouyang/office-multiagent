# 迭代总结 · v1.0.0-p0.1 · 项目脚手架 + Docker 联动

> 对应计划：PLAN-1.0.0.md Phase 0。本文件是「每步完成写总结」纪律的第一篇。

## 1. 目标
把"多 Agent 办公助手"从设计文档落地为**可运行的项目骨架**：目录结构、Docker 联动（frontend/backend/mysql/redis/chroma）、版本纪律骨架、已验证依赖清单。本步**不做任何 Agent 业务代码**。

## 2. 做了什么
- 新建项目 `office-multiagent/`（位于 AIAgent 工作区下）。
- `docker-compose.yml`：5 个服务同处 `office-net`，backend `depends_on` 三件套健康态，前端 nginx 反代 `/api` → backend（NDJSON 必须 `proxy_buffering off`）。
- `backend/`：FastAPI 骨架，`/api/v1/health` 联动探测 MySQL/Redis/Chroma（chroma 缺失不致命）；`core/{config,db,redis_client,chroma_client}.py`；`chroma_client` 懒加载 chromadb 以便测试免装重依赖。
- `frontend/`：nginx + `public/index.html` 状态页（调 `/api/v1/health` 渲染三件套状态）。
- `db/init.sql`：建 `user/model_pool/pool_model/session/task/subtask/agent_run/tool_call_log/asset/task_source/wallet/token_ledger`（对应设计文档 §六/§十三/§十四）+ 最小种子。
- `backend/requirements.txt`：从主仓已验证清单 `cp` 而来（`pip install --dry-run` 全图零冲突）。
- `docs/PLAN-1.0.0.md`：可执行分阶段计划。
- `tests/`：`test_smoke.py`（免服务）+ `test_health.py`（集成，默认 skip）。

## 3. 否掉的方案（最值钱）
- **否掉「本地从零手写前后端」**：按点7 直接 Docker 化，容器联动即可，省去本地构建链路。
- **否掉「后端直连 chromadb 重依赖导致测试必须装 chromadb」**：chroma 客户端懒加载，app 导入与冒烟测试免装 chromadb（几百 MB）。
- **否掉「mysql 端口乱映射」**：初稿误把 `BACKEND_PORT` 映射进 mysql，已改为 `3306:3306` 仅本地调试。
- **否掉「首次 `docker compose up` 由 Agent 自动跑」**：拉镜像+构建属重耗时，按点5 交回显式执行（见 README/PLAN §6）。

## 4. 验证
- `pytest backend/tests/test_smoke.py`：app 导入 + `/` + `/api/v1/health` 结构断言通过（免服务）。
- `docker compose config`：compose 文件语法校验通过（沙箱 Docker 29.6.1 / compose v5.2.0 可用）。
- 远程可达性：沙箱 `ssh ubuntu@42.192.111.82` 通（点6 能力确认，`/opt` 剩 26G）。
- **未自动跑**：`docker compose up` 全栈实跑（点5 谨慎）；`test_health.py` 集成（需 live 服务，默认 skip）。

## 5. 风险 / 遗留
- `db/init.sql` 种子密码为占位 `__CHANGE_ME__`，上线前必须改；迁移后续走 alembic（Phase 1）。
- Chroma 镜像用 `latest`，生产应 pin 版本；或按 §12.3 直接复用共享 RAG 的 Chroma（改 `CHROMA_HOST`）。
- 网关（NestJS 中间层）尚未建，当前 backend 直出 NDJSON（Phase 2 补）。
