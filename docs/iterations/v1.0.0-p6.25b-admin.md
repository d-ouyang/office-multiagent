# v1.0.0-p6.25b — 管理端最小版（用户列表 + 充值 + 账本）

**类型**：功能（P0：配额闭环的另一半）｜ **日期**：2026-10-23
**起因**：quota 门会把任务暂停，但**没有任何充值入口**——只能手工改库，真实场景等于死锁。

## 一、边界与权限

- **权限**：`role ∈ {admin, superadmin}`。两道闸：
  1. 网关 `JwtAuthGuard`（第一道，`/api/v1/admin/*` 前缀判定，非管理员 403）；
  2. 后端 `_require_admin`（权威，按自带 user 表再判一次）。
  纯函数 `isAdminPath` / `hasAdminRole` 单独可测（`/api/v1/administrator` 不能被误判为管理端——单测抓到过一次）。
- **范围**：用户列表（含余额、可搜索）、充值、单用户账本。**不做**：改角色、禁用户、模型池配置（留后续）。

## 二、接口

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| GET | `/api/v1/admin/users?q=&limit=` | 用户列表（LEFT JOIN wallet 取余额；用户名/工号模糊搜索） |
| POST | `/api/v1/admin/users/{id}/recharge` | 充值 `{amount, note}`；amount 1~10,000,000 |
| GET | `/api/v1/admin/users/{id}/ledger?limit=` | 最近流水（任务账 + 充值） |

## 三、实现要点

- `TokenPool.credit()`：`UPDATE wallet ... +amount` → 行数 0 则 `INSERT`（新用户首次充值不必先建钱包）→ 落 `token_ledger(kind='recharge', note='备注（操作人 N）')`。金额 ≤0 直接拒（防冲成负数）。
- 账本新增 `kind`（task/recharge）与 `note`；`/quota` 的流水也带回这两个字段（用户自己能看到充值记录）。
- 前端：侧栏「⚙ 管理（用户与额度）」入口（仅管理员可见）→ 独立管理页：搜索、余额、行内充值（数量+备注）、展开流水。**入口显隐不是安全边界**，后端才是。

## 五、已知限制

- 单页表格，未分页（用户量大再加）；无操作审计表（账本 note 里有操作人）。
