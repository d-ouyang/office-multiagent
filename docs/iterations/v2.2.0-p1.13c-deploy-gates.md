## p1.13 ❌ rsync 步失败

- **根因 1**：F4 用 sudo 建的 `/opt/office/scripts` 是 **root 属主**——CI 的 rsync
  以 ubuntu 身份跑，写不进（F4 部署脚本与 CI 同步身份不一致）；
- **根因 2**：`.github-token`（F4 runner 健康监控凭据）**不在 rsync 排除清单**，
  被 `--delete` 删掉——监控 token 险些丢失；
- **修复（hot1）**：服务器 chown ubuntu + workflow rsync 加 `--exclude ".github-token"`；
- token 已恢复（ubuntu 属主、600 权限）。

## p1.13b ❌ 评测门禁步失败

- **根因 1**：E3 门禁的 venv 建在 `/opt/office-test-venv`——**/opt 对 runner 用户
  只读**；
- **根因 2**：服务器缺 `python3.12-venv` 包（ensurepip 不可用）；
- **修复（hot2）**：`VENV=$HOME/office-test-venv` + 服务器补装 python3.12-venv；
- 修复后 runner 环境全量 563 手动复验全绿（55s）。

## 教训（三条，均已固化为纪律）

1. **sudo 建的目录会破坏 CI rsync 身份一致性**——/opt/office 内任何 CI 同步路径
   变更必须用 runner 用户身份做；
2. **服务器上为 CI 建的新依赖（venv/目录/凭据）必须先确认路径对 runner 用户可写**，
   /opt 是 root 的，$HOME 才是 runner 的；
3. **fine-grained PAT 无 workflows:write**——失败的部署不能 workflow_dispatch 重触发，
   一律走新 tag（pN.M.b/c 惯例）；失败的 tag 永不重打。
