## 一句话

## A · 意图能力声明（`intents.requires`）

**为什么**：路由预检原本只看 `capability_guards`（"订单"→query_orders、"读取文件"→read_document），
是**说法级**映射——每加一个工具、每换一种说法都要人肉同步，2026-11-16 漏的就是"文件"。

**做法**：每个意图在 `planner.yaml` 里声明 `requires`（这个意图的 Agent 必须有哪些工具），
`Plan.requires` 聚合，预检合并"意图级 requires ∪ 实体级 guards"两源。

**两源为何不能互相替代**（实施中修正了原计划的判据）：

- `requires` 表达"这个意图需要什么能力"——防**配置漂移**（改 agents.yaml 挪走工具时自动兜住）；
- `guards` 表达"这句话里出现了什么"——防**意图判错**（读文件被小模型判成 rag 时，靠"读取文件"实体拉回）。
- "读取文件"不是意图而是任务形态，写不进 requires。原计划"删光文件类 guards"的目标**不可达**，
  已改为两条真判据：配置自洽护栏（`requires ⊆ Agent 工具池`）+ 工具池被改坏时自动改道。

## B · 文档分段读（`read_document(offset, limit)`）

**为什么**：整读超上限就截尾。真跑事故（2026-11-17）：2.4 万字文档的第 10 章被切掉，模型只能
"按规律推断"；9.3 万字的文档更不可能一次读完。

**做法**：`offset` 起始位 + `limit` 本次上限（受 `doc_read_max_chars` 二次约束），
返回 `has_more` / `next_offset`。越界 offset 直接报错（不返回空串让模型猜）。

**真链路**：9.3 万字 / 20 章文档 → **2 次 read_document**（第二次带 `offset=50000`）→
答出「第 20 章上限 100000 元」并引用原文。此前无论怎么读都到不了末尾。

## C · 文件名自我纠正

**为什么**：原计划是"区分能力缺失/信息缺失"，但 p1.3 的路由修正已经消掉了"没有工具"那一类。
剩下的真实痛点是**文件名差一两个字符**（`smoke_md` vs `smoke-long.md`）被当成"文件不存在"→ 反问用户。

**做法**：`FileNotFoundError` 附 `difflib` 相似候选（≤3 个）+ 明确"直接重试，不要向用户索要已存在的文件"。
不改任何权限语义——路径越界仍在 `ValueError` 分支。

## p2.1 · 单步上限与任务上限的死锁（真链路抓到的）

第一次真链路验证直接 `paused_budget`，只调了 1 次工具：

```
单步上限 50000（p1.4 调的） == 任务上限 50000（TASK_TOKEN_HARD_LIMIT 缺省）
→ 读一份 5 万字文档，第一次调用就把任务预算打满
```

**修**：`task_token_hard_limit` 50000 → **200000**（≥ `doc_read_max_chars × 2`），
compose 与 `.env.example` 同步，并加护栏测试把"两个数必须拉开一倍以上"钉死。

> ⚠️ 部署注意：生产 `.env` 若写死了 `TASK_TOKEN_HARD_LIMIT=50000`，会覆盖新默认，需同步改。
