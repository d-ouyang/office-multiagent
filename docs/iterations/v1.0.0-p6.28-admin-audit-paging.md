# v1.0.0-p6.28 — 管理端体验补齐（审计日志 / 分页 / 统一下拉框 / 代续跑确认）

**类型**：功能（对照 RAG 管理端做差距分析后的四项补齐）
**日期**：2026-10-23
**起因**：用户看了 rag-qa-system 管理端截图后点单：「下拉框的问题、列表分页的问题，office 有日志记录吗？有没有单独看审计日志的地方？代续跑点击直接续跑啥都不可见？没有弹窗解释和二次确认吗？」

## 〇、先调研（参考不照搬）

读完 RAG 的 `admin-console`（TracesView/AuditView/UsersView/ConfirmDialog/ui.ts）与 `core/audit_repo.py`，提炼出四条可迁移的设计，**代码不照搬**（RAG 是 Vue+Element Plus，office 是 React+裸 CSS）：

| RAG 的做法 | office 的落地 |
| --- | --- |
| 审计表**没有** update_time/deleted_at，仓储层只有 record/list | 同样：`audit_log` 无这两列；`audit_repo` 只有 `record/list_logs/count_logs`（单测断言没有 update/delete） |
| 动作**白名单**（拼错即抛错） | 同样：`ACTION_LABELS` 10 个动作，未登记动作抛 `AuditRefused` |
| 敏感内容**抛错拒绝**（不是静默丢） | 同样：键名命中 password/token/secret 或值含 bcrypt 特征串 → `AuditRefused` |
| `el-pagination`（total, prev, pager, next） | 轻量 `Pager` 组件（总数+页码范围+每页条数），语义一致 |
| 全局 `ConfirmDialog`（danger/确认文案） | 受控 `ConfirmDialog`（title/text/bullets/danger） |

## 一、审计日志（p6.28a）——从 0 到 1

- **表**（迁移 `0010_audit_log`）：id / actor_user_id / actor_username / actor_role / action / target_type / target_id / target_label / detail(JSON) / ip / created_at。**无 update_time/deleted_at**。
- **仓储** `core/audit_repo.py`：只写只读 + 动作白名单 + 敏感拦截 + `record_safe()`（审计失败只记日志，绝不让充值因审计挂了而失败）。
- **埋点**（8 类动作）：管理端登录成功/失败、登出、改密、充值、用户池分配、池新建/删除/成员设置、代续跑。
- **管理端独立登录**（顺带解决"登录审计放哪"）：`POST /admin/login` 放在**后端**（审计表在这边，且后端本就有 bcrypt+PyJWT）；JWT 与网关同密钥同 claims（sub=employee_id/tv），两端 token 互通。网关 `routes.yaml` 把该路径设为 public。
- **改密也搬到了后端**（`POST /admin/password`）：验旧密→改密→`token_version+1` 踢旧登录态→返回新 admin token；审计只记"改了"，不记任何密码内容。
- **前端「审计日志」板块**：动作/对象下拉 + 关键词 + 分页；**detail 按动作翻译成人话**（充值→"充值 8,000 tokens / 充值后余额 32,926 / 备注"；登录失败→"原因 用户名或密码错误"），排查的人不该自己翻译键名。

## 二、列表分页（p6.28b）

- 后端 `admin/users`、`admin/tasks`、`admin/audit-logs` 全部改为 `page/page_size` + 返回 `total`（口径：筛选后总数）。
- 前端 `Pager`：共 N 条（from-to）+ 每页条数 + 页码窗口（≤7 全展开，越界 `…` 折叠）+ 上/下页；筛选变化自动回第 1 页。
- 纯函数 `pageWindow` 有单测（靠前/居中/靠后/小总数四种形态）。

## 三、统一下拉框（p6.28c）

- 原生 `<select>` 样式不可控、放不了说明文字 → 轻量 `Select`（按钮 + 浮层 + 选中态 + hint + Esc/方向键/回车键盘可达）。
- 替换三处：任务状态筛选、用户池列（带"1 人"提示）、审计动作/对象筛选。

## 四、代续跑确认与结果可见（p6.28d）——直接回应用户的批评

- **确认弹窗**：标题「确认代该用户续跑这个任务？」+ 明说**续跑 = 按原请求重新跑一遍，不是从暂停处接着跑**；列出任务内容、归属用户与暂停原因、**已完成的步骤会重新执行、消耗记在原用户账上**、**操作会留痕（审计记录操作人与原任务 ID）**；取消/确认续跑（danger 红）。
- **结果弹窗**：完成后展示 终态 / 消耗 tokens / 新任务 ID（不再是"点了啥都看不见"）；失败也明示原因。
- 执行中按钮进入「续跑中…」禁用态。

## 五、验证

- ✅ 三套测试：pytest **295 passed / 3 skipped**（新增 `test_audit.py` 16 例：白名单/敏感拦截/无 update-delete/登录审计/改密踢号/审计接口筛选分页/充值埋点/列表分页）；jest 40（+routes.yaml 公开路由不改测试）；vitest **80 passed**（+pageWindow/renderDetail）。

- ✅ Playwright：登录页、用户表（分页 + 池下拉展开）、代续跑确认弹窗（文案完整）、**完整走通 确认→代续跑→结果弹窗**（终态 single、3,716 tokens、新任务 ID）、审计日志页（含人话明细）。

## 六、已知限制

- 审计目前覆盖**管理端写操作 + 登录态**；任务本身的执行明细在 `message.trace`（另一套），未并入审计页。
- 登出记账依赖前端调用（token 无状态，强杀页面不会记登出）。
- 分页是 offset 翻页（数据量小）；任务表后续量大可改游标。
