# 迭代总结 · v1.0.0-p6.3 — 真流式管道（打字机）+ 编排异常体面收尾

> 任务 1/5（顺序 1→2→4→3→5）。Tag：`v1.0.0-p6.3`。解决用户验证反馈的核心体验问题：
> "目前还是突然全部返回展示，而不是逐字展示"。

## 1. 根因（先说透，再修）
旧管道：`/tasks` 里 `run_task` **同步跑完整个编排**（LLM 全部生成完）才返回 events 列表，
StreamingResponse 才开始吐——LLM 生成期间客户端零字节，完成后所有 delta 瞬间涌出。
前端渲染层没问题（delta 到达即渲染），卡在后端数据管道。

## 2. 做了什么
- `core/llm.py`：新增 `chat_stream()`——httpx `stream=True`，逐 chunk 回调 `on_chunk`；
  DeepSeek R1 等模型的 `reasoning_content` 回调 `on_thought`（思考也能实时展示）；
  usage 从流式末块取（`stream_options.include_usage`），token 结算不受影响。
- `orchestration/brain.py`：LlmBrain 流式模式（`stream=True`）——
  **混合策略**：LLM 输出以 `{` 开头 → ReAct JSON，等完整解析（工具步骤不逐字）；
  其他输出 → 自然语言终答，**边收边推 on_content**（真打字机），`Step.streamed=True` 防
  run_react 重复整段发；reasoning 已流式发过则 Step.thought 置空（防重发）。
  **协议升级为"二选一"**：A. 工具 JSON / B. 直接写自然语言终答（不包 JSON）——终答可逐字流式。
- `react.py`：`Step.streamed` 字段；final 分支跳过整段重发。
- `graph.py`：single/multi 的 brain 装配 `stream=True` + on_content/on_thought 接主 emitter；
  **修 multi 子任务事件不进流的旧疾**（runner 原来 emitter=子 emitter 且无 emit 回调，
  事件全丢）——改用主 emitter（seq 共享单调，测试断言兜住）；
  `run_task` 加 `sink` 回调（每事件实时外推）+ **编排异常体面收尾**（error 事件 + done("failed")，
  前端不再卡 streaming）。
- `api/routes.py`：`/tasks` 改 **worker 线程 + queue + 同步 gen**——编排在 worker 跑，
  事件经 sink 实时入队，gen 逐条 yield（Starlette 自动线程池消费，事件循环零阻塞，
  继承 p6.1 的阻塞修复成果）。
- 前端：`MarkdownView` 流式期间 **80ms 节流**（每 chunk 重解析太频；视觉仍打字机）。
- `config/agents.yaml`：rag_retrieval 提示词加"**最多检索 2 次**"——真跑发现 LLM 把
  "不理想就再试"执行成 9 次检索（110s 才收敛），真跑驱动提示词收敛。

## 3. 否掉的方案（最值钱）
- **不模拟切片打字机**（拿到完整文本按块 emit）：视觉像但假——真流式下用户能在 LLM 生成时
  就看到开头，且 chunk 间隔真实；mock 的间隔还得猜网速。
- **JSON 协议不逐字推**：ReAct 的 action JSON 必须等完整才能解析，强行逐字只会推一半坏 JSON；
  终答走自然语言直出才配得上逐字——协议二选一由此而来。
- **不用 asyncio.Queue**：编排是同步 LangGraph，worker 线程 + 线程安全 queue 最直白，
  同步 gen 由 Starlette 丢线程池，不碰事件循环。

## 4. 验证
- `pytest`：**121 passed / 3 skipped**（+8：chat_stream chunk/usage/reasoning/500、brain 流式
  自然语言逐字/JSON 不逐字/thought 不重发/错误/usage）。
- **真链路逐字实测**（curl -N 带时间戳）：终答阶段 **173 个 content_delta**，1-2ms 间隔
  连续到达，0.87s 打完——打字机成立；工具步骤/planner/status 均实时到达。
- 前端：tsc + vitest 21 + vite build 全绿；容器已重建。

## 5. 风险 / 已知遗留
- LLM 仍偶发把"任务已完成"塞进 JSON 的 action（未知工具→CAPABILITY_MISSING 自愈一轮），
  提示词已强调，观察为主，不为单次坏输出加工程码。
- R1（reasoning）模型的思考流已接 on_thought，但 R1 的 JSON 协议遵循度弱于 V3——如需
  R1 做主力 brain 需专项观察（当前默认 deepseek-chat）。
