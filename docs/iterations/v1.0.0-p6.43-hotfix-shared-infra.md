# v1.0.0-p6.43 — 上线首日 hotfix：共享网络 DNS 冲突 + init.sql 列漂移 + 输入条宽度

上线（p6.42）当天用户实测报了 4 个问题，全部定位修复。

## 1. RAG 间歇性「服务离线」+ 管理端「认证服务暂时不可用」（重大，根因同一个）

**症状**：qa.nianan.site 刷新时好时坏；admin.nianan.site 登录报「认证服务暂时不可用」。

**根因：共享网络上的 DNS 服务名别名冲突——p6.42 部署引入。** office 的 prod compose 服务名叫
`backend / gateway / frontend`，加入 `rag-qa-system_default` 网络后，compose 会把服务名注册为
该网络的 DNS 别名；而 RAG 栈的服务**也叫** `backend / gateway / frontend`（只是 container_name
叫 rag-*）。于是网络里 `backend` 同时指向 `rag-backend` 和 `office-backend`，Docker DNS 轮询：

- rag-gateway 的上游是 `http://backend:8000`——打到 office-backend 时，`/api/v1/system/health`
  等路由不存在 → 404 → 前端显示「服务离线」、登录判定不可用。实测 10 次里 8 次 404。
- 同理 office-gateway 的上游 `backend` 也有歧义（office 自己的请求随时可能打到 RAG 后端）。

**修复**：prod compose 服务名全部加 `office-` 前缀（`office-backend/office-gateway/office-frontend`
+ 显式 container_name）；前端 nginx 上游改用 `frontend/nginx.prod.conf`（指向 office-gateway，
volume 挂载，不影响开发用的 nginx.conf）；`.env` 的 `GATEWAY_BACKEND_URL` 同步改。

**验证**：修复前 health 10 次里 8 次 404；修复后 **10/10 全 200**，rag-gateway 日志 5 分钟内
0 个 404/ERROR；管理端登录报错从「认证服务暂时不可用」变为正常的「用户名或密码错误」
（判定链路已通，剩余属凭据本身）。

**教训（已写进 compose 注释）**：多个 compose 项目共享一个 docker 网络时，**服务名必须全局唯一**——
服务名即 DNS 别名，重名 = 静默轮询到错误容器。

## 2. office 发消息 500：init.sql 列漂移（message.trace）

**根因**：代码读 `SELECT role, content, trace, created_at FROM message`，但 `db/init.sql` 的
message 表没有 `trace` 列（迁移 0003 加的，init.sql 没同步）——和 p6.35 的 `runtime_setting`
是同一类漂移，只是这次漂在**列**上。本地库是迁移上来的所以没事，office 生产库是全新灌的
init.sql 所以必炸。

**修复**：
- 生产库 `ALTER TABLE message ADD COLUMN trace MEDIUMTEXT NULL`；
- 仓库 `db/init.sql` 补上该列；
- **新增列级护栏** `test_init_sql_columns_cover_required`：REQUIRED_COLUMNS 是线上真实 schema
  的列清单快照，init.sql 缺任何一列测试即红（p1.2c 只比表名，防不住这类漂移）。

**验证**：发消息 NDJSON 流正常（HTTP 200，planner/DeepSeek 全链路工作）。

## 3. 上传 500

与问题 1 同源：office-gateway 的上游 `backend` 解析歧义，multipart 请求随机打到 RAG 后端。
DNS 冲突修复后，上传实测 HTTP 200（文件落库 dev/smoke_upload.md）。

## 4. 底部输入条不占整行

PromptBar（bits 组件）写死 `--pb-w: 400px`——那是它作为独立小组件的宽度，进工作台当主
composer 必须放开。修复：`styles.css` 加作用域覆盖 `.composer-wrap .prompt-bar { --pb-w: 100% }`，
不改组件本身（bits 组件独立使用行为不变）。

## 第 5 问（用户确认）：共享到底是什么粒度

**容器共享、数据分离**：mysql/redis/chroma 三个容器与 RAG 共用；office 用 rag-mysql 里独立的
`office` 库 + 专用账号、redis db 2、chroma 独立 collection，互相不可见。office 自己的
backend/gateway/frontend 三容器完全独立。
