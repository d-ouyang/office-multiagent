# v2.0.0-p2.1 · 反馈数据模型与接口

## 1. 目标

点赞/点踩闭环的数据层与 API：`message` 加反馈当前态列 + `message_feedback` append-only 流水表（迁移 0013），提交/取消接口，消息列表带出当前态。

## 2. 交付

- **迁移 `0013_message_feedback`**（原生 DDL）：
  - `message` 加 4 列：`feedback / feedback_tags / feedback_comment / feedback_at`（当前态，列表快速渲染）；
  - 新表 `message_feedback`：append-only 流水（message/session/user/rating/tags/comment/created_at，3 个索引）。
- **`core/feedback_repo.py`**：
  - `submit()`：插流水 + upsert 当前态——二次点踩覆盖当前态、旧信息保留流水；点赞不携带原因（tags/comment 清空）；
  - `cancel()`：只清当前态，流水不删；
  - 校验：rating 白名单、tags 白名单（8 个，与 PLAN §4.2 一致）、comment ≤200、**dislike 必须至少 1 tag 或有 comment**；
  - `get_message_for()`：归属 + `role=assistant` 校验（越权/非 assistant → None → 路由 404 同形）。
- **接口**（网关透传由 routes.yaml 既有 `/api/v1` 通配覆盖，无需改网关）：
  - `POST /sessions/{sid}/messages/{mid}/feedback` → `{ok, feedback:{rating,tags,comment,at}}`；
  - `DELETE /sessions/{sid}/messages/{mid}/feedback` → `{ok, cancelled}`（cancelled=False 表示本来无反馈）；
  - `GET /sessions/{sid}/messages`：每条消息带 `id`，assistant 消息带 `feedback` 当前态对象。
- **纪律**：init.sql 同步（message 加列 + 新表）；`test_migrations.py` REQUIRED_COLUMNS 更新（message 4 新列 + message_feedback 整表）。

## 3. 方案取舍与否掉项

- **当前态 + 流水双写**而非只靠流水 latest：列表渲染零额外 join；一致性由同事务保证。
- **tags 白名单服务端校验**：防脏数据；前端弹窗用同一份 8 项清单（PLAN §4.2）。
- 时间戳由 Python 侧传参（不用 `CURRENT_TIMESTAMP(6)` 字面量）：迁移/建库走 MySQL，单测夹具走 SQLite，两端可移植。
- 管理端查询接口归 p2.3（意见反馈页一起做）。

## 4. 测试（test_feedback.py 新增 10 例 + 6 处存量夹具补列）

- repo：like 提交/取消且流水保留、dislike 无原因拒绝、未知 tag 拒绝、comment 超长拒绝、**二次点踩覆盖当前态且流水两行都在**、like↔dislike 切换、归属/角色校验。
- API：提交/取消往返（列表当前态跟随）、dislike 无原因 400 `BAD_FEEDBACK`、越权/非 assistant/未登录 404·401 同形、二次点踩列表只显最新。
