# v2.0.0-p1.0 · tool_calls 基线、能力表与 golden

## 1. 目标

为原生 tool_calls 改造建立不可漂移的起点：逐模型确认 tools / 流式 tool_calls 能力，冻结六类 golden 和既有 NDJSON 事件契约；本步不切运行协议。

## 2. 交付

- `ModelEntry.supports_tools: bool | None` 三态字段：未点测 `None`、支持 `True`、不支持 `False`，供 p1.5 auto fail-closed 使用。
- 当前 10 个对话模型逐模型真点测，非流式与流式均通过，`models.yaml` 明确登记 `supports_tools: true`。
- `scripts/probe_tool_calls.py`：可重复点测，不打印密钥，不改配置。
- `tests/golden/tool_calls_cases.json`：合法单工具、多工具、缺参、未知工具、纯终答、流式终答。
- `test_tool_calls_baseline.py`：golden 完整性、事件契约、call id/arguments、对话模型能力登记护栏。
- 能力详情见 `docs/tool-calls-能力基线.md`；2.0.0 总计划 `docs/PLAN-2.0.0.md` 同步入库。

## 3. 方案取舍与否掉项

- **不凭厂商宣传页标支持**：文档和实际兼容层可能不一致，统一以真实 HTTP 响应和可解析 tool_calls 为准。
- **不用 False 表示未点测**：False 与 None 语义不同，避免把“尚未测”误当“厂商不支持”。
- **本步不实现 llm 协议面**：避免能力基线和行为改造混在一个不可回滚提交里。
- 点测复用线上容器已有密钥，但只执行 stdin 脚本，不复制进镜像、不重启服务、不写业务数据。

## 4. 测试

- 分支基线：pytest 390 passed / 3 skipped；vitest 99 passed。
- p1.0 定向：baseline + models 初测 13 passed；补能力登记护栏后复跑 14 passed。
- 真点测：10/10 模型非流式 HTTP 200 且 tool_calls 合法；10/10 流式 HTTP 200 且增量可累积还原。

## 5. 验收与回滚

- 六类 golden 已冻结；NDJSON 未变；能力表无未点测对话模型。
- 回滚本提交即可删除能力字段和 golden，不影响现有 JSON ReAct 运行路径。

## 6. 后续

p1.1 为 Registry 补 JSON Schema 与 `describe_openai()`；p1.2 扩展 llm 非流式/流式协议面。multi 与并行 tool_calls 不在本步放开。
