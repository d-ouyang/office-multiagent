# 迭代总结 · v1.0.0-p6.21 — 模型只标思考与视觉，销售报表缺项不算完成

> Tag：`v1.0.0-p6.21`。

## 1. 目标
三个新模型在列表里只按思考和视觉区分。销售报表必须同时有时间范围、指标、口径和数据来源，数字不能由模型编写。

## 2. 做了什么
- 去掉 LongCat-2.0、Hy4-preview、Qwen3.5-9B 列表上的参数规模、工具、续写、Coder、长文本和 Vibe Coding。LongCat 和 Hy4 只标思考。Qwen3.5-9B 标思考和视觉。
- `sales_report` 必填起止日期和指标。口径按指标写死，并复述城市、状态等筛选。数据来源固定为订单表和 `query_orders`。缺时间或指标、查询失败、分组被截断时 `complete` 为 false，不给出可当作完成的正文。
- 不要某状态时用 `exclude_status`，这句话会出现在口径里。

## 3. 否掉的方案
- 不把口径交给模型写。它会漏项，或者写成和查询不一致的话。
- 不在缺时间时默认查全部订单。时间范围是完成条件，缺了就停。

## 4. 验证
- 不给时间和指标时，缺的是这两项，没有报表正文。
- 2025 年 1 月上海实付合计为 30.50，订单数 2，口径里有城市。
- 排除已取消后，全年订单数为 2。

## 5. 风险
- 模型仍可能忽略 `complete` 自己写一份报表。提示词要求它不能这么做，对话里还没看过一次真实提问。

## 6. 下一步
在对话里问一次「2025 年 1 月上海实付金额的销售报表」，看它是不是只转述工具结果。
