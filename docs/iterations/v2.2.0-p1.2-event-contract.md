## 字段语义（契约文档）

- `trace_id`：跨 run/跨服务链路追踪（Phase B2 网关入口生成注入；缺省空 = 未启用）。
- `tenant_id`：租户标识（当前单租户，预留）。
- `payload`：**横切元数据层**（归因/计量/step_id），与 `data` 分工：data=业务体（前端消费），payload=横切层（事件流合并与审计消费），互不混放。
- 序列化：新事件带空缺省值全字段输出（前端按未知字段忽略）；**run_trace.summarize 读 `ev.get("type")/("data")` 对新字段透明**。

## 设计决策（不确定时拍板）

1. **emit() 不开 per-event payload 传参口**：`payload` 与 `visual()` 构造器的 data 业务键撞名（`data.payload`），且归因元数据是 run 级一致——统一走 emitter 构造注入（`default_payload`），emit 签名零变化。将来 per-event 需求（Phase C 的 step_id）再评估开口子。
2. **payload 进事件用浅拷贝**（`dict(self.default_payload)`）：单事件突变不污染同 run 其他事件（测试钉死）。
3. **不压缩序列化**（不用 exclude_defaults）：全字段输出协议显式、体积增量可忽略，避免 exclude 语义误伤 ts/data。
