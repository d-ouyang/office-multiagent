# v2.0.0-p2.10 · 反馈回执契约收敛（rating）+ 磁盘防护

## 真根因（Playwright 线上实测定位）

p2.8 修复后用户仍报"实心一瞬打回空心"。用 Playwright 真实浏览器实测：**取消能保持、点赞 2s 后被打回**，且打回窗口内无任何 API 重载——纯前端状态回退。curl 生产 POST 回执：

```
{"ok":true,"feedback":{"id":165,"feedback":"like",...}}   ← 评分字段名是 feedback
```

前端 MessageFeedback 类型期待 `rating`。`submitMessageFeedback` 返回的 state 里 `rating=undefined` → `setFeedback(state)` 后 `rating=null` → 空心。**根因：GET messages 列表用 `rating`（session_repo 投影），POST 回执用 `feedback`（feedback_repo.current_state 直接吐 DB 列名），两个接口契约不一致。** p2.8 的本地单测没抓住：单测 mock 的回执是前端自造的（含 rating），真实后端回执从未进入单测。

## 修复

1. `feedback_repo.current_state()` 字段名 `feedback` → `rating`（对齐消息列表契约）；POST/DELETE 回执随之正确。
2. 前端 `submitMessageFeedback` 契约守护：回执缺 rating → 抛错走失败路径（回滚 + 红字），契约再坏不会静默空心。
3. 部署 workflow 末尾加磁盘防护（builder prune --keep-storage 4g + dangling image prune，if: always()）。

## 验证方式升级（用户第 2 问的落实）

新增 `/tmp/office_fb_test4.mjs` Playwright 真实浏览器验证脚本（登录 → 打开历史会话 → 取消保持 / 点赞保持 / 6 连点节流计数 / 恢复无反馈），**部署后对线上直接跑**。后续前端行为类改动一律：单测 + 本地/线上 Playwright 脚本双绿才打 tag。
