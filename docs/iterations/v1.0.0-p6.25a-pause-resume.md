# v1.0.0-p6.25a — 多原因暂停与续跑（用户主动 / 配额不足 / 中途报错）

**类型**：功能（P0：真实使用断点）｜ **日期**：2026-10-23
**起因**：p4.3 验证时撞到 `balance=0` → 任务被暂停后**既没有充值入口、也没有续跑接口**，用户只能改库+重打一遍。

## 一、暂停原因全盘点（这次要兼顾的）

| 原因 | 触发点 | 现状处理 | 可否继续 |
| --- | --- | --- | --- |
| `quota` 配额不足 | 任务开始前 reserve 失败 | 保留：`interrupt()` + `quota_paused` 事件 | ✅ 充值后续跑（原本一步没跑，零成本） |
| `user` 用户主动暂停 | 流式中点「停止」 | **新增**：协作式取消（步骤边界检查） | ✅ 继续重跑 |
| `error` 中途报错 | LLM/工具/编排异常 | **改**：从「失败终态」变成可恢复的 `paused_error`（保留原文，可一键重试） | ✅ 重试 |
| `input` 等待用户补充信息 | Agent 反问"请提供文件名" | 现状：直接答复结束（不是暂停） | ⏸ 预留枚举，后续做"暂停等回复" |
| `timeout/预算耗尽` | `max_iterations` 触顶 | 现状：带 cap 正常收尾（有结论，不是暂停） | — 不纳入 |
| `permission` 审批门 | 高风险动作（写文件/扣费）需人工确认 | 未实现 | ⏸ 预留，未来用 LangGraph `interrupt` 接审批 |

## 二、设计要点

1. **协作式取消**：`core/runs.py` 运行登记表（run_id → Event + owner）；暂停接口置位，`run_react` 每步 LLM 调用前、`run_dag` 每层/每子任务前检查，命中抛 `RunCancelled` 一路收尾。**为什么不强杀线程**：Python 无法安全终止线程，硬杀会丢连接/半写状态；步骤边界退出最多多花一步。
2. **重跑式续跑（不是断点续跑）**：checkpointer 是内存 `MemorySaver`（进程重启即丢、多副本不可用），所以 resume = 按原请求重跑，新任务 `retry_of` 指回原任务、原任务标 `resumed`。对 quota（还没跑）零成本；对 user/error 会重复计费但跨重启可靠。**真正的断点续跑**（持久化 checkpoint）列入后续。
3. **暂停只落 task 行、不落消息**：避免续跑时历史里出现"半截对话"导致上下文重复；前端靠横幅（读 `/tasks?status=paused_*`）恢复提示。
4. **取消/报错按预扣额结算**（actual=estimate，不退）：防"发起即暂停"套取退款；`task.tokens_used` 同步记该值，账实相符。
5. **归属校验**：运行中的任务还没 task 行，暂停靠登记表里的 owner_id（防越权暂停）；已落库任务靠 `task → session → user` join。

## 三、接口

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| POST | `/api/v1/tasks` | 原有；现同时写 `request_json`（text/attachments/model/effort）供续跑 |
| POST | `/api/v1/tasks/{id}/pause` | 暂停运行中任务（409 NOT_RUNNING / 403 越权） |
| POST | `/api/v1/tasks/{id}/resume` | 续跑/重试，返回 NDJSON 流（409 NOT_RESUMABLE） |
| GET | `/api/v1/tasks/{id}` | 任务详情（含 pause_reason/pause_payload） |
| GET | `/api/v1/tasks?status=&session_id=` | 我的任务列表（前端恢复横幅用） |

## 五、验证

- ✅ pytest：**262 passed, 3 skipped**（新增 `test_pause_resume.py` 16 例：登记表/越权/协作取消/暂停落库/续跑 retry_of/409/404/401）。
- ✅ 真实全栈：① 用户暂停 → 任务在 `analyze_table` 后停下，`done=paused_user`，task 行 `pause_reason=user`；② 续跑 → 新任务 `done`、`retry_of` 指回原任务、原任务标 `resumed`、tokens 22170；③ 余额置 100 → `paused_insufficient_quota`（payload balance=100/needed=2000）→ 充值 50000 → 续跑 `single` 成功、5019 tokens 入账；④ 账本 `reserve/settle` 两行配对 + 充值行（kind=recharge）。
- ✅ 前端：暂停横幅 + 「继续」按钮（`pauseText` 单测 3 例）。

## 六、已知限制

- 取消信号在进程内（单 backend 实例）；多副本要换 Redis 发布订阅（接口不变）。
- 多 Agent 任务被暂停后重跑，会重新执行已完成的子任务（重复计费）。
- 预留但未做：`input`（暂停等用户补充）与 `permission`（高风险动作审批）。
