# v1.0.0-p6.34 — PDF 中文字体修复（CFF 轮廓坑 + 失败可见化）（2026-10-24）

## 现象

真机跑「再出一份，换成 pdf」用例，`write_document` 报：
「没有可用的中文字体，PDF 未生成。请安装思源黑体……」。

## 根因（报错文案自相矛盾）

- 思源黑体**早就装在容器里**（p6.32 起 Dockerfile 带 `fonts-noto-cjk`），但装了等于白装。
- Noto CJK / 思源黑体的 `.ttc` 是 **CFF（PostScript）轮廓**；reportlab 的 `TTFont`
  只认 **TrueType（glyf）轮廓**，注册直接抛
  `TTFError: postscript outlines are not supported`。
- 旧代码 `except Exception: continue` 把这个异常**静默吞掉**，候选链走空后报
  「没有字体」——表现为「装了字体仍报没有字体」。
- matplotlib 图表不受影响（matplotlib 能吃 CFF），坏的只有 PDF 嵌入这一条路。

## 修复

1. **Dockerfile**：加装 `fonts-wqy-microhei`（文泉驿微米黑，TrueType 轮廓，reportlab 可内嵌）。
   `fonts-noto-cjk` 保留——matplotlib png 图表仍靠它。
2. **`tools_write.py::_cjk_font()` 重写**：
   - 候选只列 TrueType 轮廓字体（`_CJK_FONT_CANDIDATES` 常量：wqy-microhei →
     wqy-zenhei → DroidSansFallback → Arial Unicode → Hiragino）；
   - 常见字体目录（`/usr/share/fonts` 等）按文件名兜底扫描，防发行版路径漂移；
   - `PDF_FONT` 环境变量仍是最高优先级；
   - 单个字体注册失败**写 WARNING 日志**（文件名 + 异常），不再静默；
   - 最终报错文案纠正：明确「TrueType 轮廓；思源黑体/Noto CJK 是 CFF 轮廓不支持」。

## 验证

- 容器内端到端：真实生成中文 PDF（23KB），pypdf 抽回文本完整
  （「上海 2025 年合计销售金额 1,234.5 万元，环比增长 12%」），无康熙部首污染。
- 本地全量：见 RELEASES 条目（`test_tools_write.py` 新增 2 例：失败路径报错含
  TrueType 指引；注册失败留 WARNING 日志——旧版被静默吞掉的分支）。
- 本地回归：`test_tools_write.py` 7/7 通过（macOS 走 Arial Unicode 路径）。

## 教训（沉淀）

- reportlab 内嵌字体必须 TrueType 轮廓；「装了字体」不等于「reportlab 能用」。
- 字体注册失败严禁静默 continue——副作用失败必须日志可见（与教训③同源）。
