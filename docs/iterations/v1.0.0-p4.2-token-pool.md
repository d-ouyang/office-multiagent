# 迭代总结 · v1.0.0-p4.2 — Token 池两段式扣减 + 中断 + 断点续跑（Phase 4 收口）

> 对应计划：PLAN-1.0.0.md Phase 4 / v1.0.0-p4.2。Tag：`v1.0.0-p4.2`。至此 **Phase 4 全部完成**。

## 1. 目标
落地设计文档 §十四：**token 池两段式扣减**（reserve 预扣 / settle 结算，原子防并行超额）、**余额不足中断**（`paused_insufficient_quota`）、**checkpointer 断点续跑**。接进编排图与 `/tasks` 端点。

## 2. 做了什么
- `core/token_pool.py`：`TokenPool`（引擎可注入）——`reserve`（原子 `UPDATE wallet SET balance=balance-:a WHERE user_id=:u AND balance>=:a`，影响行 0=余额不足）+ `settle`（按 `reserved-actual` 补差）+ `balance`；落 `token_ledger`。参数化 SQL，MySQL/SQLite 通用。
- `orchestration/graph.py`：加 `quota` 门节点——reserve 失败 `interrupt()` 暂停（checkpointer 存档），`Command(resume=...)` 充值后续跑（resume 后重试 reserve）；完成 `settle`。`build_graph`/`run_task` 增 `token_pool`/`user_id`/`estimate` 参数，`resume_task` 辅助续跑。
- `POST /api/v1/tasks`：增 `user_id`/`estimate`；带 user_id 走 token 池，余额不足推 `quota_paused`。
- 测试：65 passed（新增 test_token_pool 5 + test_graph_token 3）。

## 3. 否掉的方案（最值钱）
- **不自建钱包行**：reserve 对无钱包行直接 `rowcount=0`→余额不足，避免 `INSERT IGNORE`（MySQL）/`ON CONFLICT`（SQLite）方言分裂，保持一条原子 SQL 跨库。
- **settle 基线 actual=0 全额退**：StubBrain 无真实 LLM 用量，先验证 reserve→settle 往返与不超额；真实 token 计数随 LLM brain（Phase 5）接入。
- **checkpointer 用 MemorySaver**：跨请求续跑需持久化 checkpointer（SqliteSaver/MySQL），留作部署态下一步；本轮用 MemorySaver 验证中断/续跑机制本身。
