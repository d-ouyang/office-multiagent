# 迭代总结 · v1.0.0-p6.6 — 文档上传入口（任务 5/5）

> 顺序 1→2→4→3→5 之任务 5（最后一个）。Tag：`v1.0.0-p6.6`。

## 1. 做了什么
- `POST /api/v1/documents`（multipart）：落盘 `data/upload/<username>/`（**按登录用户分目录**）。
  护栏：只取 basename（`../`/绝对路径全拍平）、格式白名单（.md/.txt/.pdf）、10MB 上限、
  空文件拒；失败 4xx 如实。`python-multipart==0.0.20` 入 requirements。
- 前端：输入条 📎 上传按钮（隐藏 file input + FormData，**不手设 Content-Type**——
  浏览器自动带 boundary）；成功/失败 5 秒提示条。
- `read_document` 工具描述补"文件不存在时不要反复重试"（真跑发现 LLM 会反复猜路径）。
- compose：`./backend/data` 卷 :ro → **rw**（上传要写；路径护栏不依赖卷权限）。

## 2. 验证
- `pytest`：**138 passed / 3 skipped**（+6 上传测试：ok/traversal 拍平/格式/大小/空/401）。
- **真链路**：上传 dev/my-doc.md（104B）→ 任务“读一下我上传的 dev/my-doc.md” →
  `read_document{'file_name':'dev/my-doc.md'}` → 逐字总结（打字机叠加验证）→ done。
- 前端：tsc + vitest 21 + vite build 全绿。

## 3. 踩坑（真跑才炸）
1. **data 卷 :ro 上传 500**：卷权限挡死写——改 rw（read_document 的安全靠路径护栏，
   不靠卷只读）。
2. **网关 multipart 无风险已验**：`fixRequestBody` 只重写被 body-parser 解析过的 body，
   multipart 原样透传（上传成功即证）。
3. **LLM 猜路径**：用户说"我上传的 my-doc.md"，LLM 先猜 `my-doc.md`（缺用户目录）→
   工具如实报不存在 → 第二次纠正 `dev/my-doc.md` ✅ 自愈。工具描述加"不要反复重试"后
   收敛（max_iterations=10 兜底仍有效）。
