# 迭代总结 · v1.0.0-p5.1b — 业务 Agent 提示词化 + 真 LLM 端到端（Phase 5）

> 承接 p5.1a。Tag：`v1.0.0-p5.1b`。用户授权从 langChain 项目搬运 DEEPSEEK_API_KEY 至
> `backend/.env`（git-ignored；后续换新 key 直接覆盖该行）。

## 1. 目标
PLAN Phase 5 任务①：**每个业务意图一个专属 Agent**（角色提示词 + 工具白名单，配置驱动），
multi 子任务同步接入真 Brain；真 LLM 端到端验证（含"能力缺失→如实告知"）。

## 2. 做了什么
- `config/agents.yaml`（新）：7 个 AgentSpec（6 业务 + general 兜底）——name / tools 白名单 /
  system_prompt。visualization、image_restore 工具池暂空（对应能力未接入）。
- `orchestration/agents.py`：AgentSpec 加载（agents_config 自动定位）+ `get_agent_spec`
  （未注册回落 general）+ `build_registry_for_spec`（按白名单裁剪工具；未知名跳过=对该 Agent 能力缺失）。
- `brain.py`：**角色指令与 JSON 协议分离**——AgentSpec 只写角色与行为边界，ReAct 的 JSON 输出
  协议统一由 brain 拼接（`_PROTOCOL_TMPL`），避免 7 份提示词各自漂移。
- `graph.py`：single_node 与 **multi 子任务**均按 agent_type 取 spec 装配（角色+白名单工具+Brain）。
- 环境搬运：DEEPSEEK_API_KEY → `backend/.env`（用户授权；.env 确认 git-ignored）。
- **`tests/conftest.py`（新，关键）**：autouse fixture 强制单测无 LLM key → make_brain 回落
  StubBrain。缘由：key 入 .env 后 pytest 读到，单测开始真调云端（41.8s、烧钱、非确定性，
  余额断言被真用量打破）——已抓已堵；"真 LLM 验证只走显式 smoke"成为铁律。

## 3. 否掉的方案（最值钱）
- **协议不进 yaml**：JSON 输出格式是协议不是提示词，写进 7 份提示词必然漂移；统一在 brain 拼。
- **工具白名单裁剪而非全局暴露**：image_restore 看不到 db_query——Agent 只见其职，越界工具
  从提示词层面就不存在。
- **单测与真 LLM 隔离**（conftest）：宁可单测全 mock，也不让 100 个用例悄悄烧 key。

## 4. 验证
- `pytest backend/tests`：**103 passed / 3 skipped，4.55s**（+8：agents 注册表 7 + brain 角色注入 1）。
- **真 LLM 端到端**（uvicorn + curl /tasks）：
  - 任务"查公司年假制度"→ rag_retrieval Agent → LlmBrain 决策调 `rag_retrieve` → 回答注明
    依据文件（《…05_考勤管理制度.md》第九条）；
  - 任务"修复老照片"→ image_restore Agent（无工具）→ **如实告知"没有图像处理能力"** 并给替代建议
    ——§四.5"能力缺失不假装"在真 LLM 上成立。
