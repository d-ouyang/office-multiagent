# 迭代总结 · v1.0.0-p1.2b — NDJSON 事件封装（任务 2）

> 对应计划：PLAN-1.0.0.md Phase 1 / v1.0.0-p1.2b（任务 2「NDJSON 事件封装」）。Tag：`v1.0.0-p1.2b`。

## 1. 目标
按设计文档 §15.1 / §15.3 落地 **NDJSON 事件协议**：定义异构事件类型 + 信封（`run_id / turn_id / seq`）+ 类型化构造器 + orjson 序列化，给 Phase 3 起的 Agent 编排一个统一、可测、前端可消费的事件出口（沿用 §12.1「NDJSON 非 SSE」结论）。

## 2. 做了什么
- 新增 `core/events.py`：
  - `EventType` 枚举：`thinking_delta / content_delta / tool_call_start / tool_call_end / observation / status / quota_paused / artifact / source / error / done / task_summary`（覆盖 §15.1 + §15.3）。
  - `Event` 信封（pydantic）：`type / run_id / turn_id / seq / ts(ms) / data`；前端按 `seq` 排序、按 `run` 分组折叠。
  - `EventSequence`：每 run 单调自增 `seq`，跨副本合并后仍有序。
  - `RunEventEmitter`：自动填 `run_id/turn_id/seq/ts`，并为每个事件类型给**类型化构造器**（协议自文档、字段可测）。
  - `encode_line` / `parse_line` / `iter_ndjson` / `to_ndjson_bytes`：一行一事件、以 `\n` 结尾；orjson 序列化（缺则回退标准 json，测试轻量环境可用）。
- 新增 `/api/v1/demo/stream`（脚手架）：一条 canned NDJSON 序列演示全协议类型，供前端/网关联调，Phase 3 真实编排前占位，不依赖外部服务。

## 3. 否掉的方案（最值钱）
- **不把 orjson 提到模块顶层 import**：与 yaml/chroma 一致懒加载，保证 app 导入/单测在轻量环境（无 orjson）也能跑；缺则回退标准 `json`。
- **不在 `data` 里散落魔法键**：每个事件类型的字段由构造器固化（如 `tool_call_start` 固定 `tool_id/name/input`），前端可按类型断言字段，改动集中在构造器一处。
- **`parse_line` 对未登记 type 从严抛错**（pydantic ValidationError）：协议向前兼容靠"新增枚举值"，不靠"静默忽略未知事件"——否则前端会把不认识的事件当空数据处理，难排查。
- 不做 SSE 双协议：§12.1 已拍板 NDJSON，本模块只服务 NDJSON。
