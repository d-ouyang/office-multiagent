# v1.0.0-p6.27 — 管理端独立应用（登录/菜单/个人中心）+ 代续跑 + 模型池配置

**类型**：功能（用户点单的三件事）｜ **日期**：2026-10-23
**点单原文**：「继续任务 1 和 2，但是管理端也要有自己独立的登录页面、侧边菜单和个人中心」

## 一、管理端独立应用（p6.27a）

- **独立登录页**：`/admin` 未登录 → 管理端自己的登录页（ADMIN 徽标 + 「登录管理端」）。复用同一账号体系（user 表），但**独立 token**（`localStorage.office_admin_token`，与工作台 `office_token` 互不影响）+ 角色校验：非 admin/superadmin 直接拒（"该账号没有管理员权限"）。
- **独立路由**：`/admin`、`/admin#<tab>`（刷新直达并保持面板）；极简路由（popstate/hashchange 同步），不引 react-router。**修了一个真 bug**：原来 `/admin` 未登录会先掉进工作台登录页，变成"双重登录"——现在管理端优先，自己管登录态。
- **侧边菜单**：ADMIN 品牌 + 5 个板块（用户与额度 / 用量概览 / 任务监控 / 模型池 / 系统状态，各带 hint）+ 返回工作台 + 底部用户 chip。
- **个人中心**：管理员信息（用户名/工号/角色）+ 修改密码（成功后轮换 admin token）+ 退出管理端。

## 二、任务监控代续跑（p6.27b）

- 任务表新增「操作」列：`paused_*`/`failed` 行显示「代续跑」按钮。
- 后端 `POST /admin/tasks/{id}/resume`：与自助续跑共用 `_resume_task_impl`，区别只在不校验 owner；**消耗仍记在原任务 owner 头上**，操作人 id 落 `request_json.operator`（可追溯）。
- 前端流式消费 NDJSON，只取 done/error 做结果提示（不展示完整对话），完成后自动刷新列表。

## 三、模型池配置（p6.27c）——先补了一个"配了也白配"的洞

实读代码发现：`model_pool`/`pool_model` 两张表**没有任何代码消费**，池可见性其实由 `models.yaml` 的 `pool_ids` 驱动，而 `user.model_pool_id` 是个没人用的整数。所以除了界面，还必须让配置真正生效：

- **`/models` 按登录用户的池过滤**（§十三 池隔离落地）：不显式传 `pool` 时，按 `user.model_pool_id → model_pool.name` 过滤；未登录/未分配=可见全部（兼容旧行为）。
- **成员判定规则**：DB `pool_model` 有行 → **以 DB 为准**（含 `enabled=0` 的显式关闭）；无行 → 回落 yaml 的 `pool_ids`（新模型加进 yaml 即默认可见）。⚠️ 中间踩过一个语义坑：最初把"显式关闭"存成"不写行"，结果又回落 yaml 重新可见——改成全量写入（含 0）后才自洽。
- **池身份=名字**（default/staff/admin，与 yaml 对齐；init.sql 加种子，dev=admin 池、chen=default 池）。
- **接口**：`GET/POST /admin/model-pools`、`PUT /admin/model-pools/{id}/models`（全量）、`DELETE /admin/model-pools/{id}`（有用户在用 → 409）、`PATCH /admin/users/{id}/pool`（分配/不限制）。
- **界面**：「模型池」板块 = 左池列表（新建/删除/用户数）+ 右模型矩阵（checkbox + 保存成员）；「用户与额度」表新增「池」列（下拉即改即生效）。

## 五、已知限制

- 模型池界面只配置**对话模型**（in_dialogue）；逻辑模型池后续按需开放。
- 「代续跑」在管理端只给结果提示，不展示完整对话流（想看过程让用户自己在工作台续跑）。
- 管理端与工作台共用后端 JWT 密钥；两套 token 独立但都可被改密同时踢失效（预期行为）。
