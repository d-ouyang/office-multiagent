# 迭代总结 · v1.0.0-p6.16 — 把结论写成 md 或 docx

> Tag：`v1.0.0-p6.16`。图表仍不做。

## 1. 目标
分析做完之后，能留下一份 md 或 docx，而不是只停在对话里。

## 2. 做了什么
- `write_document` 接收标题、正文和格式。格式只接受 md、docx。xlsx、pdf、图片会直接拒绝。
- 文件写到当前用户上传目录的 `_out/w-<编号>.md` 或 `.docx`。正文超过 8 万字拒绝。
- 传入 `clean_id` 时，文末附上原文件名、列和清洗后行数。这个编号不存在时不创建文件。
- 工具成功后事件流带上产物。回复下方显示「生成文件」，点击走现有预览。docx 预览的是抽出的文字。
- 通用、分析和报表 Agent 可以调用。口头总结不再为了总结本身去调工具；用户要文件时仍要调用它。

## 3. 否掉的方案
- 不在这一步做柱状图、折线图或 xlsx。图的数据必须来自清洗表，和写文章不是同一件事。
- 不把生成文件拍扁到上传目录根上。预览只认 `_out/` 下固定编号，避免 `../` 被当成合法文件。
- 不由工具改写模型给出的数字。来源脚注只说明表从哪来、有多少行，避免把没算过的汇总值写进去。

## 4. 验证
- `tests/test_tools_write.py`：md 内容、拒绝 xlsx、docx 含结论和来源、无效 clean_id 不落文件、事件流出现产物。
- `test_preview_generated_markdown`：`_out/w-....md` 能打开，`_out/../secret.md` 返回 400。
- 前端：生成文件按钮点击后把 `_out/w-1.md` 交给预览。

## 5. 风险
- 正文数字仍依赖模型照抄 `analyze_table` 的结果。脚注只能证明用了哪张表，不能逐句核对金额。
- docx 只保留标题、段落和以 `- ` 开头的条目，复杂 Markdown 表格不会原样变成 Word 表格。

## 6. 下一步
