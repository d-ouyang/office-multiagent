# 迭代总结 · v1.0.0-p5.0a — 共享网关：配置驱动路由表 + 多上游 + 横切加固（Phase A/B/C）

> 对应《共享网关迁移设计》。认证放 **B（自建共享网关，office 网关演进）**。Tag：`v1.0.0-p5.0a`。

## 1. 目标
把 office 网关从"单上游硬编码"演进成**配置驱动、多上游的共享 API 网关**，落地迁移设计的 Phase A（路由表骨架）、Phase B（多上游接 RAG）、Phase C（横切加固）。

## 2. 做了什么
- **`gateway/config/routes.yaml`**（新）：路由表——每个 upstream 一个业务后端，routes 按 path 前缀匹配、`public` 决定免 token；支持外部前缀（RAG 用 `/rag`，转发剥成 `/api/v1/*`）；`base_url` 支持 `${VAR:-默认}`。
- **`proxy/route-table.ts`**（新）：纯解析逻辑（`matchUpstream` 最长前缀 / `stripPrefix` / `resolveRoute` / `isPublicPath`）+ 带缓存加载器。未命中 → fail-closed 非公开。
- **`proxy/proxy.controller.ts`**（重构）：单 `@All('*')` 通配按路由表解析上游、动态建/复用每上游代理、剥前缀改写 `req.url`；保留 NDJSON 不缓冲/`fixRequestBody` 顺序纪律；**透传 correlation-id** 到上游（Phase C）。
- **`auth/guards/jwt-auth.guard.ts`**：公开判定改为 `@Public()` 元数据 **或** 路由表 `public`（守卫与代理共用同一张表）。
- **Phase C 横切**：`AllExceptionsFilter` 统一错误体 `{error:{code,message,requestId}}`；`FixedWindowCounter` + `RateLimitMiddleware` 每 IP 固定窗口限流（配置驱动，0=关闭，多副本为每实例计数→全局限流需 Redis，已标注）。
- 配置/接线：`configuration.ts` 加 `rateLimitMax/rateLimitWindowMs`；`main.ts` 注册 filter + 按上游打印；`app.module.ts` 挂限流中间件；compose/env 示例加 `RAG_BACKEND_URL`、`GATEWAY_RATE_LIMIT_*`；`js-yaml` 入依赖。
- **修两个镜像/依赖坑**：gateway 运行阶段漏 `COPY config/`（routes.yaml 不进镜像会启动崩，同 backend 那类坑）；`js-yaml` 忘加入 dependencies。

## 3. 否掉的方案（最值钱）
- **不各上游一个 `@All` 前缀路由**，改用单通配 + 路由表解析：上游增减只改 YAML，不动代码/不重排路由注册顺序。
- **公开判定不放 @Public 元数据**（代理路径）：改由路由表驱动，避免"加了上游却忘了标 public"的静默 401；网关自身路由（/api/health、/api/internal/ping）仍用 @Public。
- **限流默认 600/IP/分、可关**：不搞激进默认值吓到开发；多副本严格限流明确留 Redis，不假装内存计数能全局。

## 4. 验证
- `tsc --noEmit` 通过；`nest build` 产 dist 成功。
- `jest`：**26 passed / 4 suites**（新增 route-table 10 + rate-limiter 4；e2e 增 3：多上游剥前缀 + correlation-id + NO_ROUTE）。
- e2e 实证：`/rag/api/v1/qa` 带 token → 命中 rag 上游、剥成 `/api/v1/qa?x=1`、上游收到同一 `X-Request-Id`；无 token → 401；未命中 → 404 NO_ROUTE。
- ⏸️ RAG 上游的**真实连通**（host.docker.internal:8000 打到宿主 RAG FastAPI）属部署态，待本机验证；RAG 侧"信任网关注入身份 + 去双认证"属 rag 仓改动，见设计文档 Phase B。
