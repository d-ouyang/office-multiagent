# v2.0.0-p1.1 · Registry 参数 Schema 与 OpenAI tools 导出

## 1. 目标

tool_calls 模式的地基：每个工具在注册处声明参数 JSON Schema，Registry 能导出 OpenAI 兼容 `tools[]`，缺 Schema 的工具被明确挡在导出之外。

## 2. 交付

- `ToolRegistry.register(..., parameters=None)`：注册即收 Schema；非 dict 直接 `ValueError`（fail-fast）。自动补齐 `type=object` / `properties` / `additionalProperties=false`。
- `describe_openai()`：`[{type:"function", function:{name, description, parameters}}]`，只导出有 Schema 的工具，稳定排序。
- `schema_of()` / `schema_incomplete()` / `copy_into()`：查询、护栏与白名单裁剪共用；`build_registry_for_spec` 改走 `copy_into`，Schema 随白名单一起搬运。
- 13 个工具全部补 Schema（含 remember/recall、query_orders 的 filters/metrics/nodes 等嵌套结构），参数名与工具实现 kwargs 一一核对过。
- 测试：Schema 归一化 / 非 dict 拒绝 / 缺 Schema 排除 / 白名单携带 / **全工具池 `schema_incomplete()==[]` 护栏**。

## 3. 方案取舍与否掉项

- **Schema 写在注册处而非 agents.yaml**：参数名与函数签名强耦合，放代码里能被同一处测试校验；agents.yaml 仍只管白名单与提示词。
- **`additionalProperties` 统一 false**：与「schema 过宽导致乱参」红线对齐，模型多传字段在 p1.2 校验层会得到明确错误而不是静默吞掉。
- **不自动从函数签名生成 Schema**：隐式推断掩盖「描述与实现漂移」，显式声明更符合 fail-closed。
- 旧 `describe()`（文本提示词用）原样保留，json 协议路径零影响。

## 4. 测试

- 定向：test_agents 12（原 7 + 新 5）+ test_memory 3，15 passed；test_tools / test_react / test_brain 回归 22 passed。
- 全量回归见 p1.2 收口（与协议面同一批全量跑）。

## 5. 验收与回滚

- `build_default_registry(None).describe_openai()` 返回 13 个工具且参数均为 object；json 模式行为不变（describe 未动）。
- 回滚 = revert 本提交，`register` 回到三参签名，无数据影响。
