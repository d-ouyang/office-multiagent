# 迭代总结 · v1.0.0-p1.1 — 后端核心骨架前置：鉴权 stub + 模型注册表 + 日志

> 对应计划：PLAN-1.0.0.md Phase 1（前半）。Tag：`v1.0.0-p1.1`。

## 1. 目标
把"Docker 联动脚手架"升级为可扩展内核的前半：① 配置固化（日志/鉴权/模型 key）；② 内部鉴权 stub（fail-closed，对应 RAG 的 `internal-auth.client.ts`）；③ 配置驱动的模型注册表（对话大模型 + 逻辑小模型分列，全云端）；④ 日志与可观测性（设计文档 §十八）。同时收口用户 6 点指令中的 GitHub 远端、README、日志、模型配置。

## 2. 做了什么
- `core/config.py`：新增 `log_level`/`log_format`/`jwt_secret`/`internal_shared_secret`/`models_config`/云端 key 字段。
- `core/internal_auth.py`：`X-Internal-Token` + hmac 恒定时间比对，fail-closed；`/api/v1/internal/auth/ping` 受保护路由。
- `backend/config/models.yaml` + `core/model_registry.py` + `/api/v1/models`：对话大模型（deepseek-chat/reasoner、qwen-plus、glm-4、kimi，按模型池过滤）与逻辑小模型（bge-m3 embedding / bge-reranker-v2-m3 / decision-llm，`in_dialogue:false` 不进对话列表）全部配置驱动、全云端，无硬编码。
- `core/logging.py`：JSON 行日志 + `CorrelationMiddleware`（请求链路 `correlation_id`）+ `log_agent_step`/`log_token_audit`/`log_duration` 语义化辅助；设计文档新增 §十八。
- 远端 `d-ouyang/office-multiagent` 经 GitHub API 建立并推送（master + 两 tag）；README 精简；`.env.example` 补全；`db/init.sql` 的 `pool_model` 种子加 `deepseek-reasoner`。

## 3. 否掉的方案（最值钱）
- **不在本迭代实现用户 JWT 签发/验签（passport-jwt ↔ PyJWT 打通）**：那是 Phase 2 网关的事。本迭代只落后端这一侧的「服务间」鉴权 stub，避免和网关耦合；用户 JWT 的 `jwt_secret` 字段先占位，打通留到网关。
- **不把 embedding/reranker/decision 写进代码常量**：明确走 YAML 配置（`in_dialogue:false` + `role`），与对话大模型同表管理，新增模型只改 YAML 不碰代码。
- **不把 pyyaml 提到模块顶层 import**：app 导入保持轻量（单测/health 无需装 pyyaml），只在真正读注册表时才 `import yaml`（与 chroma_client 的懒加载一致）。
- **日志默认 JSON 而非 text**：远端集中采集/检索友好；本地调试可切 `LOG_FORMAT=text`。
