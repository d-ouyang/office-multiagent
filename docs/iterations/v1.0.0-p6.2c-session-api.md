  （初始加载/新建/切换拉历史）；ChatMessage 支持历史终答直渲染（content 字段）。

## 2. 否掉的方案（最值钱）
- **历史不存事件流只存终答**：thinking/工具步骤是过程不是结论，落 message 表要存 JSON  blob
  且前端渲染历史事件成本高；实时流已完整展示过程，历史回看终答+上下文足够。
- **不新增 GET /me 到后端**：身份走 Bearer 直解析（_current_user），不引 session cookie；
  与"网关认证单点"的定位一致（后端只验签+解析，不管签发）。
- **title 不建独立列**：用首条 user 消息子查询派生——少一列少一处写入口径。

## 4. 踩坑记录（都是真跑才炸的）
1. **alembic 在现有库从 base 重放**：该库由 init.sql 直建、从未 upgrade（p1.2c 决策），
   alembic_version 为空 → 从 0001 重放，种子 INSERT 引用已删的 kb_role 列而炸。
   正解：`alembic stamp 0001_initial`（标记现状）→ `upgrade head`。
2. **`sa.Text(length=...)`**：渲染出 MySQL 非法的 `TEXT(16777215)`；改 `op.execute` 原生 DDL。
3. **`DATETIME` fsp=0 + `CURRENT_TIMESTAMP(6)` 默认值**：MySQL 报 Invalid default value——
   ORM 的 DateTime(6) 在 MySQL 方言渲染丢精度；原生 DDL `DATETIME(6)` 直书才稳。

## 5. 风险 / 已知遗留
- SUBSTRING 在 SQLite 不支持（list_sessions 的 title 派生只在 MySQL 验证过；sqlite 测试
  未覆盖 list_sessions——补测或改 substr 兼容，留 minor）。
- message 无 per-user 隔离索引（session 归属已校验，量小可接受）。
- /tasks 现在强制登录身份：无 token 直连后端会 401（安全默认；demo 流不受影响）。
