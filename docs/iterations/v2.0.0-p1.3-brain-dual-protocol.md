# v2.0.0-p1.3 · brain 双协议与历史消息形态

## 1. 目标

`LlmBrain` 支持 `tool_calls` 协议路径：请求用 OpenAI `tools`，历史用 `assistant(tool_calls) → tool(tool_call_id)`，响应解析为结构化调用列表。json 路径原样保留。

## 2. 交付

- `LlmBrain(protocol=...)`：构造时经 `resolve_react_protocol` 一次性定协议（`self.protocol`）。
- `_messages_for_tool_calls()`：system（无 JSON 格式要求）+ user 任务 + 每个历史步 `assistant(tool_calls)` + `tool` 消息；观察只走 tool 角色（历史双写禁忌）；json 时代的历史步无原生 id 时合成 `call_{i}` 保证配对。
- `_step_from_tool_calls()`：响应含 tool_calls → `Step(calls=[{id,name,arguments,parse_error}])`，content 归为 thought；无 tool_calls → 自然语言终答。
- 流式：content 先按"可能是终答"逐字推（保真打字机）；若流末发现 tool_calls，已推片段归为思考（已知限制：厂商惯例工具轮 content 为空，影响面小）。
- system 提示词换 `_TOOLCALLS_TMPL`——**删除**强迫输出 JSON 的段落（Prompt 债务红线），纪律段保留。

## 3. 方案取舍与否掉项

- 协议在构造期定死而非每步判定：灰度观测口径稳定，避免同任务中途换协议。
- 历史 Step 无 `call_id` 时合成稳定 id（`call_{序号}`）：兼容 API 只要求配对一致，不要求厂商签发。
- 不在 brain 层做参数 Schema 校验：llm 层已保证 arguments 是 JSON object；字段级校验留给工具自身（现有工具都有兜底错误）。

## 4. 测试（test_brain.py 新增 6 例）

结构化调用返回 / 历史 tool 角色与配对 id / json 历史合成 id / 无调用即终答 / 坏 arguments 保留 parse_error / 协议解析矩阵（json·auto·tool_calls×支持·缺Schema·非法配置）。

## 5. 验收与回滚

- `settings.react_protocol=json`（缺省）下 LlmBrain 行为与改造前逐字节一致（存量 15 个 brain 用例未改断言）。
- 回滚 = 配置回 json；代码回滚 revert 本提交。
