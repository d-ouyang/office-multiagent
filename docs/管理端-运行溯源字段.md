# 管理端 · 运行溯源字段

一条运行按任务 id 聚合。trace 缺失时工具序列为空，并标明「无 trace」，不补造步骤。

| 字段 | 来源 | 含义 |
| --- | --- | --- |
| id | task.id | 与当次 run_id 相同 |
| username | session → user | 办公用户 |
| status / pause_reason | task | 完成、暂停、失败及原因 |
| text | task.text | 用户原文 |
| model | request_json.model | 当时选的对话模型 |
| tools / tool_summary | assistant trace 的 tool_call_start | 实际工具顺序 |
| artifacts | trace 的 artifact | 生成的文件名 |
| validation_mismatch / validation_note | observation 里的结果校验 | 终答数字对不上时的说明 |
| rag_username | 工具返回 | 真正发给知识库的账号，目前是服务号 |
| office_username | 工具返回 | 这次提问的办公用户 |
| identity_mismatch | 上面两个不一致 | 管理端用浅红色标出 |

销售链路若调用了 `query_orders` 或 `rag_retrieve`，会按这个顺序出现在工具序列里。
